## Правила написания кода на 1С

> Префикс правила указывает происхождение:
> - `[std#NNN]` — прямая норма официального стандарта 1С; NNN — номер страницы на v8std.ru или its.1c.ru;
> - `[платформа]` — подтверждённый факт устройства или ограничения платформы 1С: не норма стандарта с номером страницы и не совет по стилю, нарушение ведёт к ошибке или к невозможности сделать задуманное. Источник — в конце строки;
> - `[рекомендация]` — практическая рекомендация, основанная на стандартах и методиках 1С, но не являющаяся их прямой нормой;
> - `[правило проекта]` — обязательное соглашение команды для этого проекта; действует, пока явно не изменено в `CLAUDE.md` проекта;
> - правила в секции «Политика шаблона» — локальный выбор шаблона (ослабляемый под проект), отдельного суффикса не требуют.
>
> Правила, называющие общие модули БСП (ОбщегоНазначения, СтроковыеФункции, ДлительныеОперации и т.п.), действуют в конфигурациях на БСП соответствующей версии; вне БСП — возможности платформы или механизм проекта.
> При сомнении, конфликте правил или зависимости от версии платформы сверься по протоколу из `.claude/rules/mcp.md`. Не выполняй проверку перед каждым обычным применением правила.
>
> По умолчанию следуй стандарту 1С и готовому механизму БСП, не изобретая своё там, где есть штатное. Стандарт, метод платформы или метод БСП не выдумывай по памяти — сверяй по первоисточникам: документации 1С/ИТС, синтакс-помощнику платформы и исходникам БСП в проекте (скиллы шаблона покрывают лишь малую часть БСП).

- [std#404] Формы открывай через ОткрытьФорму() с параметрами, не через ПолучитьФорму().Открыть().
- [std#418] Не используй `Сообщить()`. На сервере: `ОбщегоНазначения.СообщитьПользователю()`, на клиенте: `ОбщегоНазначенияКлиент.СообщитьПользователю()`.
- [std#437] Всегда давай псевдонимы полям через `КАК`: `Контрагенты.ИНН КАК ИНН`.
- [std#448] При копировании строк между таблицами значений, табличными частями и другими коллекциями со схожим составом колонок используй `ЗаполнитьЗначенияСвойств()` вместо перебора колонок.
- [std#450] Не вызывай `Записать()` для наборов движений внутри `ОбработкаПроведения`: записывать их обязана платформа при завершении обработчика. Достаточно установить `Движения.<Регистр>.Записывать = Истина`.
- [std#452] Для поиска строк `ТаблицыЗначений` по нескольким колонкам используй `НайтиСтроки()` со `Структурой` отбора, а не ручной перебор.
- [std#452] При многократном поиске в большой `ТаблицеЗначений` создавай индекс по селективным колонкам поиска. Для `НайтиСтроки()` состав полей индекса должен совпадать с составом полей `Структуры` отбора.
- [std#452] Для многократного поиска в большом `Массиве` используй `Соответствие` либо индексированную `ТаблицуЗначений`. Для единичного поиска или небольшой коллекции не создавай индекс без необходимости.
- [std#455] Порядок областей в общем модуле: `ПрограммныйИнтерфейс` → `СлужебныйПрограммныйИнтерфейс` (внутри подсистемы) → `СлужебныеПроцедурыИФункции` (внутри модуля).
- [std#455] Порядок применимых областей в модулях объектов, менеджеров, наборов записей, обработок и отчетов: `ОписаниеПеременных` → `ПрограммныйИнтерфейс` → `ОбработчикиСобытий` → `СлужебныйПрограммныйИнтерфейс` → `СлужебныеПроцедурыИФункции` → `Инициализация`. Неприменимые и пустые области не создавай.
- [std#455] Порядок областей в модуле команды: `ОбработчикиСобытий` → `СлужебныеПроцедурыИФункции`. Пустые области не создавай.
- [std#455] Область для метода выбирай по его роли, а не по тому, какая область в модуле уже есть. Перехватчик заимствованного метода размещай в той же области, где этот метод лежит в типовом модуле (обработчик события — `ОбработчикиСобытий`, служебный — `СлужебныеПроцедурыИФункции`); собственный служебный метод расширения — в `СлужебныеПроцедурыИФункции`. Нужной области нет — заведи её на своём месте в стандартном порядке.
- [std#456] Ограничение строки — 120 символов (если можно корректно перенести).
- [std#465] В обработчике `ПриЗаписи` не изменяй данные самого объекта: к этому моменту он уже записан в базу. Изменение реквизитов — не позже `ПередЗаписью`.
- [std#466] В обработчике `ПриКопировании` очищай реквизиты, значения которых не должны сохраняться в новом объекте после копирования. Конкретный перечень определяется объектом — стандарт универсального списка не задаёт.
- [std#486] Размещай логику по принадлежности: зависящую от состояния конкретного экземпляра — в модуле объекта; относящуюся к объекту метаданных, но не требующую экземпляра, — в модуле менеджера; не относящуюся однозначно к одному объекту метаданных — в общем модуле.
- [std#496] Не читай отдельные реквизиты ссылки через точку: это загружает объект целиком, включая табличные части. Используй запрос; в конфигурациях на БСП можно использовать `ОбщегоНазначения.ЗначениеРеквизитаОбъекта()`, `ЗначенияРеквизитовОбъекта()`, `ЗначениеРеквизитаОбъектов()`, `ЗначенияРеквизитовОбъектов()`.
- [std#498] Записывай событие в Журнал регистрации из кода, когда администратору нужна диагностика, которую платформа не пишет автоматически. Одна запись — одно событие; для исключения используй `ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`.
- [std#499] Не перехватывай исключения без необходимости; блок `Попытка` размещай локально вокруг проблемного вызова. Не гаси перехваченное бесследно: перевызови через `ВызватьИсключение` без потери исходной информации либо, при окончательной обработке, залогируй для администратора.
- [std#542] Для временного файла или каталога используй `ПолучитьИмяВременногоФайла()`; после завершения работы удаляй его явно, в том числе на пути обработки исключения. В веб-клиенте, где эта функция недоступна, формируй уникальное имя из `КаталогВременныхФайлов()` и `УникальныйИдентификатор`; при наличии БСП временный каталог на клиенте создавай через `ФайловаяСистемаКлиент.СоздатьВременныйКаталог()`.
- [std#542] Не передавай локальный путь к файлу между клиентом и сервером: передавай данные через временное хранилище платформы или файловые механизмы БСП.
- [std#542] Временный файл на сервере создавай и обрабатывай в рамках одного серверного вызова. Если данные должны жить между вызовами, помещай их во временное хранилище.
- [std#641] Для параметра типа `Структура` в программном интерфейсе определяй функцию-конструктор со всеми допустимыми свойствами. Вызывающий код не должен добавлять произвольные свойства или менять предусмотренный состав параметров.
- [std#641] Документируй свойства передаваемых и возвращаемых структур, а также состав и типы колонок таблиц и деревьев значений программного интерфейса.
- [std#643] Для текущей даты на сервере используй `ТекущаяДатаСеанса()`, не `ТекущаяДата()`.
- [std#647] Имена процедур и функций формируй из терминов предметной области; имя должно ясно описывать назначение метода.
- [std#647] Процедуру именуй глаголом неопределённой формы по выполняемому действию (`ЗагрузитьКонтрагента()`, не `ЗагрузкаКонтрагента()`), функцию — по возвращаемому значению (`ПолноеИмя()`, `ДатаНачалаСеанса()`), функцию-проверку — со слова `Это` или причастием (`ЭтоВнешняяЗадача()`, `ДокументПроведен()`).
- [std#678] Бизнес-логика не живёт в модуле формы — выноси в общие модули или модуль объекта.
- [std#680] Модули объекта, менеджера и сеанса оборачивай в `#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда`: иначе в толстом клиенте управляемого приложения они компилируются и выполняются на клиенте, где обращения к серверным общим модулям падают. В модуле объекта в ветке `#Иначе` вызывай исключение о недопустимом вызове объекта на клиенте.
- [std#680] Если обработчики `ОбработкаПолученияПредставления` и `ОбработкаПолученияПолейПредставления` модуля менеджера должны работать в толстом клиенте, вынеси их код за инструкцию препроцессора, а обработчики подписок на эти события размести в клиент-серверных общих модулях. На `ОбработкаПолученияДанныхВыбора` и `ОбработкаПолученияФормы` ограничение не распространяется: они вызываются только на сервере.
- [std#686] Параметру `Отказ` присваивай только `Истина` и никогда — результат булевой функции или `Ложь`; то же для `СтандартнаяОбработка` и других возвращаемых булевых параметров. Установив `Отказ = Истина`, сообщи пользователю причину: платформа покажет только общий текст «Не удалось записать...».
- [std#693] Не передавай в конструктор `Структуры` более трёх значений. Остальные свойства заполняй через `Вставить()` или присваивание.
- [std#725] Потенциально неограниченные результаты запросов обрабатывай порциями фиксированного размера; не загружай весь результат в память через `Выгрузить()`.
- [std#740] Не храни пароли, токены и другие секреты в коде, реквизитах обычных прикладных объектов и реквизитах формы. В конфигурациях на БСП используй безопасное хранилище паролей.
- [std#740] Если БСП нет и хранение секрета в информационной базе неизбежно, используй отдельный объект метаданных с минимально необходимыми правами доступа и учитывай, что такое хранение не устраняет риск полностью.
- [std#740] Секрет извлекай на сервере непосредственно перед использованием и не возвращай его на клиент. Привилегированный режим включай в вызывающем коде только на минимально необходимое время.
- [std#764] Пользовательские строковые литералы оборачивай в НСтр(): НСтр("ru = 'Текст'").
- [std#773] В обработчиках `ПередЗаписью`, `ПриЗаписи`, `ПередУдалением` объекта и набора записей — а также в обработчиках подписок на эти события — первой проверкой ставь `Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;`. При обмене объект загружается как есть, и бизнес-логика повторно выполняться не должна.
- [правило проекта] Комментарий внутри тела процедуры или функции по умолчанию не пишется. Требуется пояснение — переработай код: говорящие имена методов и переменных, ранний выход, выделение подзадачи в метод. Запрет не распространяется на документирующую шапку метода (### Документирование), маркеры доработок (### Маркеры доработок) и комментарии в тексте запроса (std#437). Ограничение наше: стандарт комментарии в теле допускает и нормирует их оформление (std#456 п. 7.2, 7.3), но писать не требует.
- [правило проекта] Единственное исключение — факт, которого в коде не видно и без которого следующий разработчик сломает работающий код. Перечень закрытый: поведение платформы, БСП или внешней системы; обходное решение со ссылкой на источник; предупреждение о контексте вызова (например, «вызывается из фонового задания»). Одна строка на один факт. Бизнес-правило, номер задачи и TODO в перечень не входят.
- [правило проекта] В теле метода запрещено в любом виде: пересказ постановки и бизнес-правил задания, пояснение самой доработки («добавлено по задаче», «раньше считалось иначе», «понадобилось для отчёта»), пересказ того, что делает соседняя строка, обоснование выбранного решения. Их дом — бриф, коммит git и номер задачи, а не модуль. Переносишь код из плана или брифа в модуль — комментарии и шапки пересматривай заново, а не копируй.
- [правило проекта] В комментарии кода не ссылайся на артефакты рабочего процесса: пути и имена файлов исходников (`src\...`, `*.bsl`, `*.xml`), файлы плана и задания, ветки git, номера чатов и сессий — внутри Конфигуратора их не существует. Допустимые ссылки — в тех комментариях, шапках и маркерах, которые разрешены: имя объекта метаданных, имя процедуры или функции, номер задачи, номер стандарта, адрес внешней публикации.
- [правило проекта] Сдавая работу, перечисли в отчёте каждый оставленный в теле метода комментарий и факт из закрытого перечня, который он фиксирует. Комментарий, для которого такого факта нет, удали до сдачи.
- [правило проекта] Закомментированный код запрещен: историю храни в git. Единственное исключение — замененный типовой код вендора, сохраненный внутри маркеров `COMMENT_OPEN`/`COMMENT_CLOSE` при доработке основной конфигурации; там, где маркеры по настройке проекта не применяются, исключения нет — заменяемый код удаляй.
- [рекомендация] Перед написанием кода проверяй в общих модулях и модулях менеджеров экспортные методы, которые можно переиспользовать.
- [рекомендация] Не создавай области внутри процедур/функций и не имитируй области декоративными комментариями-баннерами — только штатные `#Область`/`#КонецОбласти` на уровне модуля.
- [рекомендация] Не используй венгерскую нотацию: `МассивКонтрагентов` — нет, `Контрагенты` или `СписокКонтрагентов` — да.
- [рекомендация] Не используй в именах переменных имена из глобального контекста 1С (Документы, Справочники, Регистры, Метаданные, Константы и др.).
- [рекомендация] Текст запроса начинай с новой строки после `Запрос.Текст =` без отступа, строки продолжай через `|` (пример — в скилле query-writing).
- [рекомендация] Сохраняй результат запроса в промежуточную переменную, если он проверяется, используется повторно или представляет самостоятельный этап алгоритма. Для однократной выгрузки ограниченного результата допустимо `Запрос.Выполнить().Выгрузить()`.
- [рекомендация] Перед написанием запроса проверяй реквизиты метаданных (существование, имена, типы).
- [рекомендация] Не используй запросы внутри цикла — используй пакетные запросы и временные таблицы.
- [рекомендация] Результаты повторяющихся вычислений в цикле сохраняй в Соответствии и используй повторно.
- [рекомендация] В модулях форм предпочитай `&НаСервереБезКонтекста` вместо `&НаСервере`. Минимизируй переходы клиент-сервер.
- [рекомендация] В новом клиентском коде используй стиль клиентской асинхронности, заданный в «Настройках проекта» файла `CLAUDE.md`. Если выбор не сделан, сохраняй стиль изменяемого кода; если образца нет — запроси выбор. `Асинх/Ждать` выбирай только на платформе версии 8.3.18 или выше; иначе используй `Показать*` с `ОписаниеОповещения`. Режим совместимости конфигурации значения не имеет — проверено экспериментом.
- [рекомендация] Не переводи существующий рабочий код между `Показать*` с `ОписаниеОповещения` и `Асинх/Ждать` без отдельной задачи на такую миграцию. Если API предоставляет только один вариант, следуй его контракту независимо от выбранного стиля проекта.
- [рекомендация] Одно исключение логируй один раз — на границе операции, где есть контекст и принято решение об окончательной обработке; на промежуточных уровнях перевызывай без повторной записи.
- [рекомендация] Используй `ЗначениеЗаполнено()`, когда требуется проверка заполненности по правилам платформы. Если алгоритму важно различить конкретные состояния — `Неопределено`, `Null`, ноль, пустую строку или пустую ссылку — проверяй ожидаемое состояние явно согласно контракту данных.
- [рекомендация] Проверяй код на конкурентность и необходимость блокировок. Учитывай внешние транзакции (например, транзакция записи объекта).
- [рекомендация] Используй СтрШаблон() для составления строк вместо конкатенации через «+». Исключение: простая пара Префикс + Суффикс, если читается лучше.
- [рекомендация] Читай JSON в Соответствие, не в Структуру: ПрочитатьJSON(ЧтениеJSON, Истина).
- [рекомендация] Если `Структура` получена из внешнего источника либо свойство является необязательным, проверяй его через `Свойство()` или функцию БСП `СвойствоСтруктуры()`. Для обязательных свойств с гарантированным контрактом допускается прямое обращение.

### Архитектура
- [рекомендация] Используй ранний возврат для уменьшения вложенности вместо глубокой вложенности.
- [рекомендация] Приоритет модификации типового кода: подписки на события > расширения > изменение типового кода.
- [рекомендация] Перехват в расширении делается двумя механизмами: директивой в тексте модуля (&Перед/&После/&ИзменениеИКонтроль/&Вместо) и привязкой обработчика к событию формы или её элемента в свойствах формы. Типы вызова у них общие — «Перед», «После», «Вместо», — и семантика одинакова.
- [рекомендация] Тип перехвата выбирает вопрос «нужно ли вмешаться в середину типового метода». Если задача выражается обёрткой — бери обёртку и не тащи в расширение копию типового тела: для процедур это &Перед/&После, для функций и для случаев, когда нужно повлиять на параметры, результат или условно не выполнять оригинал, — &Вместо с ПродолжитьВызов(). &Перед/&После предпочтительнее &Вместо: они не подавляют перехватчики нижних расширений. Правило действует в обоих механизмах, и ПродолжитьВызов() работает как у директивы, так и у привязки к событию формы.
- [рекомендация] &ИзменениеИКонтроль бери, когда обёртка задачу не выражает и править надо внутри тела метода. Он тянет в расширение копию всего метода под контролем платформы: при изменении этого метода вендором расширение попадёт в список ошибок применения, и перехватчик придётся пересобирать вручную. Это цена вмешательства в середину, а не повод обходиться обёрткой там, где середина действительно нужна.
- [платформа] &Вместо без ПродолжитьВызов() — крайний случай: типовой код не выполнится вовсе, а изменение метода вендором пройдёт молча. Допустимо, только когда типовой метод намеренно не должен работать; решение обоснуй и перепроверяй при обновлении конфигурации. Если замещение по сути было редактированием скопированного тела — выражай его через &ИзменениеИКонтроль: там расхождение с вендором проконтролирует платформа (v8cs:change-and-validate-instead-of-around).
- [платформа] &Перед/&После перехватывают только процедуры: доступа к возвращаемому значению функции через них нет — в 1С не существует паттерна «перехватчик после метода получает результат через отдельный параметр». Обёртка функции — &Вместо с ПродолжитьВызов(); &ИзменениеИКонтроль нужен функции тогда же, когда и процедуре, — при правке в середине тела (wonderland.v8.1c.ru «Расширение модулей»; пример &ИзменениеИКонтроль на функции — диагностика v8std v8cs:change-and-validate-instead-of-around).
- [правило проекта] В формах перехватывай обработчик через привязку к событию. Директива применяется, только когда событием не обойтись: метод модуля формы не является обработчиком события либо нужно вмешаться в середину типового обработчика — тогда &ИзменениеИКонтроль. Выбор директивы в форме обоснуй.
- [рекомендация] Перед выбором &Вместо или &ИзменениеИКонтроль проверь перехватчики других расширений над тем же методом: &Вместо подавляет не только типовой метод, но и перехватчики расширений, лежащих ниже по порядку применения, причём молча; &ИзменениеИКонтроль допустим на метод только один во всей конфигурации — второй признаётся ошибочным и попадает в список ошибок применения расширения.
- [правило проекта] Один перехватываемый метод — один перехватчик на тип вызова. Несколько правок в этом методе, даже пришедших из разных задач и разных дат, объединяй в один перехватчик, сохраняя внутри его тела их маркеры, если маркеры в проекте применяются. Разные типы вызова («Перед» и «После») на один метод допустимы, когда этого требует логика; несколько перехватчиков одного типа — нет: читаемость теряется, а сопровождать и перепроверять при обновлении вендора приходится каждый.
- [рекомендация] Реальное поведение типового объекта/метода — это основная конфигурация плюс все расширения, которые его перехватывают. Перехват бывает двух видов, и в тексте модуля виден только один: директива стоит в модуле, а привязка обработчика к событию формы или элемента живёт в `Form.xml` расширения и поиском по директивам не находится. Перед анализом или изменением такого объекта проверь исходный объект и каждое расширение из каталогов `CLAUDE.md`, которое его затрагивает, — и модули, и формы. Если объект затронут расширениями — до правки кратко сообщи картину (оригинал + перехваты).
- [рекомендация] До правки перечисли, что ещё она затрагивает: перехватчики расширений над тем же методом, вызовы изменяемого метода, подписки на события, роли, обмены, регламентные задания. Список сообщи до внесения изменений.
- [рекомендация] Длительные операции (ориентир — дольше ~10 секунд) выноси в фоновые задания с индикатором прогресса; в конфигурациях на БСП — через ДлительныеОперации, не прямым вызовом ФоновыеЗадания (пример — в скилле use-bsp).
- [рекомендация] Не создавай чрезмерно крупный модуль с десятками несвязанных процедур; разделяй его по зонам ответственности.
- [рекомендация] Используй экспортный программный интерфейс модулей (`ПрограммныйИнтерфейс`), не завись от деталей их реализации.
- [рекомендация] Без преждевременной оптимизации: сначала работающий код, оптимизация — по данным замеров.

### Транзакции и привилегированный режим
- [std#783] `НачатьТранзакцию()` располагай непосредственно перед `Попытка`. Все действия транзакции выполняй в этом блоке; `ЗафиксироватьТранзакцию()` вызывай последней перед `Исключение`. В блоке `Исключение` сначала вызывай `ОтменитьТранзакцию()`, затем обрабатывай ошибку и повторно вызывай исключение.
- [std#783] При исключении в активной транзакции не обращайся к базе данных до `ОтменитьТранзакцию()`, включая неявное получение представления ссылки.
- [std#783] Не открывай явную транзакцию ради записи одного объекта или набора записей, если другого ответственного чтения и атомарных действий не требуется — платформа выполнит запись в собственной транзакции.
- [рекомендация] Транзакции делай максимально короткими, без взаимодействия с пользователем внутри.
- [рекомендация] `УстановитьПривилегированныйРежим(Истина)` применяй только в минимально необходимой области. Запоминай и восстанавливай исходное состояние на всех путях выхода, включая исключения; если исключение перехвачено только для восстановления состояния — вызови его повторно. Не выполняй внутри внешние вызовы и взаимодействие с пользователем.

### Политика шаблона (выбор шаблона, не стандарт 1С — можно ослаблять под проект, зафиксировав в CLAUDE.md проекта)
- Вложенность: < 5 уровней (жёсткий лимит)
- Параметры функции: <= 5 (жёсткий лимит)
- Не используй тернарный оператор `?()`
- Магические числа запрещены — выноси в именованные переменные
- Yoda-синтаксис запрещён: `Если Сумма = 0`, не `Если 0 = Сумма`
