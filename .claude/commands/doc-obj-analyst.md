## [ИНВАРИАНТНЫЙ АЛГОРИТМ]

### Шаг 1: Определение объектов для анализа

Ниже после этого промпта будут указаны объекты для анализа. Это может быть:
- Путь к файлу или папке
- Имя объекта конфигурации (например: "Отчет.АнализПродаж", "Документ.ЗаказКлиента")
- Содержимое XML/BSL напрямую
- Несколько объектов сразу

Также могут быть указаны опциональные параметры:
- Подробность: кратко / стандартно / максимально подробно (по умолчанию: стандартно)
- Цель документирования
- Особые акценты (источники данных, бизнес-правила, ограничения и т.п.)

**Если объекты не указаны** — спроси пользователя: "Какие объекты 1С нужно документировать? Укажите имена объектов, пути к файлам или вставьте содержимое."

### Шаг 2: Анализ каждого объекта

Если подключены MCP-серверы для работы с 1С (чтение метаданных, навигация по конфигурации), используй их для получения информации об объектах.

Для каждого объекта проанализируй:

1. Тип объекта, подсистема, область применения
2. Структура данных: реквизиты, табличные части, их бизнес-смысл
3. Используемые данные: справочники, документы, регистры (разделяй типовые и нетиповые)
4. Результирующие данные: что создаётся/изменяется
5. Бизнес-правила и проверки из кода
6. Расчётные показатели, агрегаты, условия отбора
7. Связи и взаимодействие с другими объектами

### Шаг 3: Формулирование выводов

- Описывай в терминах бизнес-логики, не технической реализации
- Явно разделяй факты и предположения
- Не придумывай функционал, которого не видно в коде

### Шаг 4: Написание документации

- Максимум ясности: откуда что берётся и что получается
- Минимум технических деталей
- Адаптируй детализацию под указанный уровень подробности

## [РЕКОМЕНДАЦИИ ПО СТРУКТУРЕ]

Результат — в формате Markdown. Структуру определяй самостоятельно, исходя из типа объекта и найденного функционала.

**Обязательные элементы:**
- Назначение объекта
- Используемые данные и источники

**Добавляй разделы по необходимости**, например:
- Результирующие данные (что создаётся/изменяется)
- Бизнес-правила и проверки
- Расчёты и показатели (для отчётов)
- Структура данных объекта (для документов, справочников)
- Связи с другими объектами
- Роли, упоминаемые в коде (если есть проверки прав)
- Ограничения (что нельзя сделать)
- Типовые vs нетиповые объекты (если используются объекты с префиксами)

**Принцип:** добавляй только те разделы, для которых есть содержательная информация. Пустые или формальные разделы не нужны.
