## [ИНВАРИАНТНЫЙ АЛГОРИТМ]

### Шаг 1: Определение объектов для анализа

Ниже после этого промпта будут указаны объекты для анализа. Это может быть:
- Путь к файлу или папке
- Имя объекта конфигурации (например: "Справочник.Номенклатура", "Отчет.ОстаткиТоваров")
- Содержимое XML/BSL напрямую
- Несколько объектов сразу

Также могут быть указаны опциональные параметры:
- Подробность описания (по умолчанию: средняя)
- Цель документирования
- Особые акценты

**Если объекты не указаны** — спроси пользователя: "Какие объекты 1С нужно документировать? Укажите имена объектов, пути к файлам или вставьте содержимое."

### Шаг 2: Анализ каждого объекта

Если подключены MCP-серверы для работы с 1С (чтение метаданных, навигация по конфигурации), используй их для получения информации об объектах.

Для каждого объекта:

1. Определи тип объекта (справочник, документ, отчет, обработка, регистр и т.п.)
2. Проанализируй метаданные и код:
   - Формы: какие есть, для чего предназначены
   - Реквизиты и табличные части
   - Команды и действия
   - Бизнес-логика и проверки
3. Определи назначение и основной функционал

### Шаг 3: Формулирование выводов

- Если назначение очевидно — формулируй уверенно
- Если есть только косвенные признаки — сформулируй как предположение
- Не выдумывай функционал, которого нет в коде

### Шаг 4: Написание документации

Используй простой, человеческий язык:
- Не перегружай 1С-терминами
- Пиши на уровне "что делает" и "зачем", а не "как реализовано"
- Адаптируй детализацию под указанный уровень подробности

## [РЕКОМЕНДАЦИИ ПО СТРУКТУРЕ]

Результат — в формате Markdown. Структуру определяй самостоятельно, исходя из типа объекта и найденного функционала.

**Обязательные элементы:**
- Назначение объекта (кратко, простым языком)
- Основные возможности / что можно делать

**Добавляй разделы по необходимости**, например:
- Описание форм для пользователя (если есть формы)
- Структура данных (для справочников — какие данные хранятся)
- Табличные части и их назначение (для документов)
- Параметры и отборы (для отчетов)
- Порядок работы / пошаговый процесс (для обработок)
- Ограничения и проверки (если есть значимые)
- Важные моменты и нюансы (если есть)
- Печатные формы (если есть)

**Принцип:** добавляй только те разделы, для которых есть содержательная информация. Пустые или формальные разделы не нужны.

**Скриншоты:** если среди входных данных есть изображения (скриншоты форм, интерфейса), используй их в документации для наглядности. Вставляй скриншоты в соответствующие разделы с подписями.
