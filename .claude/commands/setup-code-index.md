# Подключение проекта к индексу исходников `code-index`

Ты доводишь проект до состояния, в котором сервер `code-index` отвечает на поиск по коду и граф
вызовов по всем наборам исходников проекта. Индексатор один на машину: демон следит за всеми
зарегистрированными каталогами, MCP-сервер `serve` отдаёт их по HTTP на одном порту, проект
выбирается параметром `repo`. Подключение проекта — это одна секция в `daemon.toml` плюс
проектные файлы. Нормы работы с индексом — `.claude/rules/mcp.md`, порядок — скилл
`mcp-code-index`.

## Правила выполнения

- **Команда идемпотентна.** Каждый шаг сверяет фактическое состояние и доделывает только
  недостающее. Настроенное не перезаписывай: покажи текущее значение и спроси, менять ли.
- **Ничего не выдумывай про CLI и формат файлов.** Команды и формат ниже сверены с исходниками
  источника, но выпуски выходят часто, а установщик ставит последний. Сомнение —
  `bsl-indexer.exe --help`, `bsl-indexer.exe daemon --help` и `README_RU.md`
  репозитория [Regsorm/code-index-mcp](https://github.com/Regsorm/code-index-mcp), не память.
- **Каждая операция вне папки проекта — по явному подтверждению именно этой операции:**
  скачивание и установка, запись переменной окружения, автозапуск, правка `daemon.toml`,
  запуск и перезапуск процессов. Покажи команду целиком до запуска. Запуск скачанного
  установщика, регистрацию автозапуска и запуск фоновых процессов авторежим Claude Code может
  заблокировать — тогда отдай команду пользователю: он запускает её сам через `!` в сессии.
  `!` исполняет bash, поэтому команду PowerShell отдавай обёрнутой:
  `! pwsh -NoProfile -Command '<команда>'` (внутри — только двойные кавычки).
- **Вопросов пользователю — один: алиас.** Каталоги берутся из таблицы «Каталоги исходников
  проекта» паспорта, исключения и формат — этой командой. Алиас предложи сам — имя каталога
  проекта латиницей (`ut_comp`) — и дай подтвердить одним словом.
- Правишь только: `daemon.toml` в `CODE_INDEX_HOME` (добавляешь одну секцию, остальные
  не трогаешь), `src\.code-index\config.json`, `.mcp.json`, `.gitignore`, `CLAUDE.md`,
  при необходимости `.claude/settings.local.json`. Исходники, `.claude/rules/`, другие проекты — нет.
- **MCP-инструменты `code-index` в этой сессии не появятся**, даже после правки `.mcp.json`:
  серверы поднимаются при старте сессии. Проверяй по HTTP (шаг 6), перезапуск предложи в конце.
- Коммит только по команде пользователя.

## Шаг 1. Сверка состояния

Покажи одной таблицей:

| Что | Признак настроенности |
|---|---|
| индексатор на машине | `CODE_INDEX_HOME` задана в окружении пользователя, `bsl-indexer.exe` в ней отвечает на `--version` |
| автозапуск | в папке автозагрузки пользователя есть `code-index.vbs` либо задачи планировщика `CodeIndexDaemon`/`CodeIndexServe` |
| демон и сервер живы | `bsl-indexer.exe daemon status` — `running`; порт 8011 слушается |
| проект в `daemon.toml` | есть `[[paths]]` с `path` на `src` проекта |
| `src\.code-index\config.json` | существует, `exclude_dirs` содержит каталог эталона поставщика из паспорта |
| `.mcp.json` | есть сервер `code-index` с `http://127.0.0.1:8011/mcp` и `"alwaysLoad": true` |
| паспорт `CLAUDE.md` | секция «Индекс исходников (code-index)» без плейсхолдера `<АЛИАС>` |
| `.gitignore` | `src/.code-index/*` закрыт, `config.json` открыт |
| версия данных индекса | в `health` у репозитория `data_version` без признака `stale` |

Все пункты закрыты — скажи об этом и остановись. Дальше выполняй только незакрытые.

`data_version.stale` — индекс собран прежней версией индексатора: часть данных может
отсутствовать молча. Пересборку не запускай: покажи пользователю команду из ответа `health`
(`index <путь> --force`) и предупреди, что на крупной конфигурации она идёт минуты.

## Шаг 2. Машина: установка и автозапуск (один раз)

Индексатора нет — предложи штатный установщик источника. Он скачивает выпуск, распаковывает,
задаёт `CODE_INDEX_HOME` и PATH пользователя, создаёт `daemon.toml` и печатает блок для
`.mcp.json`. Покажи команду и дождись подтверждения:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/Regsorm/code-index-mcp/main/install.ps1))) `
    -Flavor bsl -Port 8011 -Repo "<алиас>=<корень проекта>\src" -RegisterAutostart
```

- `-Flavor bsl` — сборка с инструментами 1С; без неё индекс будет, а `find_references`,
  `get_register_writers`, `bsl_sql` и остальных инструментов метаданных — нет.
- `-Repo` заполняет `daemon.toml` только при первой установке: существующий файл установщик
  не трогает. Для второго и следующих проектов — шаг 4.
- `-RegisterAutostart` — папка автозагрузки пользователя, прав администратора не требует,
  окон при входе не показывает. Отдельное подтверждение: это изменение автозагрузки машины.
  Отказ — работа без автозапуска, тогда процессы придётся запускать руками после каждого входа;
  так и запиши в отчёте.
- `-InstallDir` не задавай без просьбы: по умолчанию `C:\tools\code-index`, и это же значение
  уходит в `CODE_INDEX_HOME`.

Установлен, но процессы не запущены — запусти оба без окон одной командой (её оставляет
установщик): `wscript "$env:CODE_INDEX_HOME\start-hidden.vbs"`. Файла нет — два процесса:
`bsl-indexer.exe daemon run` и `bsl-indexer.exe serve --transport http --port 8011 --config
"$env:CODE_INDEX_HOME\daemon.toml"`, оба скрыто (`Start-Process … -WindowStyle Hidden`).

Переменная `CODE_INDEX_HOME` задана установщиком только что — в текущей сессии её ещё нет:
читай значение из реестра пользователя или подставь путь установки явно.

### Обновление индексатора

Только по просьбе пользователя или когда нужного инструмента нет в `tools/list`. Установщик
поверх работающих процессов не обновляет: `bsl-indexer.exe` занят, распаковка падает
с `Access to the path … is denied`, а установщик всё равно печатает «Готово» и версию
старого файла. Поэтому по порядку, каждый шаг с подтверждения:

1. Предупреди: остановка демона прерывает индексацию всех проектов машины, сессии других
   проектов потеряют сервер до перезапуска.
2. Останови оба процесса установки:
   `Get-Process bsl-indexer | Where-Object Path -like "$env:CODE_INDEX_HOME\*" | Stop-Process -Force`.
3. Запусти установщик без `-Repo` и `-RegisterAutostart`: `daemon.toml` и автозапуск уже есть.
4. Проверь вывод: нет `denied`, в строке «установлено» — новая версия. Иначе процессы ещё живы — назад к п. 2.
5. Запусти процессы (`start-hidden.vbs`, см. выше) и проверь `health`: `ready` и `data_version`
   без `stale`. Индекс заново не собирается: демон при старте только сверяет время и размер
   файлов. `stale` — команда пересборки пользователю, как в шаге 1.

## Шаг 3. Исключения — до регистрации в демоне

Порядок важен: демон начинает индексировать сразу после регистрации, и без исключений
в индекс попадёт эталон поставщика — тогда каждый поиск будет находить типовой код дважды.

```
bsl-indexer.exe init --path <корень проекта>\src
```

Команда создаёт `src\.code-index\config.json` со всеми ключами. Задай четыре, остальные оставь:

```json
"exclude_dirs": ["cf_vendor", ".build", "build"],
"exclude_file_patterns": ["DumpFilesIndex.txt", "ConfigDumpInfo.xml"],
"languages": ["bsl"],
"repo_language": "bsl"
```

Каталог эталона поставщика называется в паспорте иначе — возьми имя оттуда. В `.gitignore`:

```
# code-index: индекс SQLite рядом с исходниками; настройки исключений версионируются
src/.code-index/*
!src/.code-index/config.json
```

## Шаг 4. Регистрация в демоне

Корень индекса — каталог `src` проекта, не корень проекта и не отдельные наборы: индексатор сам
находит `Configuration.xml` основной конфигурации и каждого расширения и сводит их в один граф,
модули расширений помечает `extension_name`. Корень проекта затянул бы `.claude`, `.tasks`,
`build`; отдельные наборы разорвали бы граф вызовов между конфигурацией и расширениями.

Один `[[paths]]` на проект, в конец `$env:CODE_INDEX_HOME\daemon.toml`, путь прямыми слэшами:

```toml

[[paths]]
path = "C:/WS/<проект>/src"
alias = "<алиас>"
language = "bsl"
```

Затем `bsl-indexer.exe daemon reload` — демон подхватывает без перезапуска. `daemon stop`/`start`
не делай: демон общий, остановка разорвёт индексацию других проектов.

**`serve` новый репозиторий не увидит**: список репозиториев он читает из `--config`
при старте, а его наблюдатель конфигурации перечитывает только языки. Признак — `health`
отдаёт прежний `mcp.repos`, вызов с новым `repo` — `unknown_repo`. Перезапусти только `serve`
(демон не трогай), с подтверждения пользователя:

```powershell
Stop-Process -Id (Get-NetTCPConnection -LocalPort 8011 -State Listen).OwningProcess -Force
Start-Process "$env:CODE_INDEX_HOME\bsl-indexer.exe" -ArgumentList 'serve','--transport','http','--port','8011','--config',"$env:CODE_INDEX_HOME\daemon.toml" -WindowStyle Hidden
```

`serve` только читает, перезапуск безопасен; открытые сессии других проектов переподключатся
через `/mcp` → `Reconnect`.

## Шаг 5. Проектные файлы

Не зависит от готовности индекса — делай, пока идёт индексация.

1. `.mcp.json` — сервер по HTTP на общий порт (stdio-запись с `command`/`args` здесь не нужна:
   демон уже индексирует, `serve` уже запущен):

   ```json
   "code-index": {
     "type": "http",
     "url": "http://127.0.0.1:8011/mcp",
     "alwaysLoad": true
   }
   ```

   `alwaysLoad` не даёт Claude Code откладывать инструменты индекса: отложенные видны агенту
   только по имени, и он уходит в `Grep` мимо индекса. Запись уже есть без ключа — допиши его.

   Затем `.claude/settings.local.json`: есть список `enabledMcpjsonServers` — он действует как
   белый список, и сервер без записи в нём в `/mcp` не появится; добавь `"code-index"`.
   Списка нет — ничего не делай, Claude Code спросит сам при старте.

2. `CLAUDE.md` — секция «Индекс исходников (code-index)» уже есть в паспорте шаблона: подставь
   алиас и каталоги из таблицы «Каталоги исходников проекта», убери HTML-комментарий. Секции
   нет (удалили при `/setup-project`) — заведи перед «Подключённые базы (MCP)» по образцу:

   | Алиас (`repo`) | Что проиндексировано | Исключено |
   |---|---|---|
   | `<алиас>` | `src` целиком: `cf`, `cfe_<Имя>`, `epf`, `erf` — в одном графе | `src\cf_vendor`, `build`, `.build` |

   Нормы в паспорт не пиши: они в `.claude/rules/mcp.md`, копия разойдётся.

## Шаг 6. Готовность и проверка

Первичная индексация типовой конфигурации — минуты, на крупной (ERP) — до десяти;
ход — в `$env:CODE_INDEX_HOME\daemon.log`. Готовность — `bsl-indexer.exe daemon status`:
у пути `ready`, не `initial_indexing`. Пока не `ready`, проверку не делай: нулевой ответ
неполного индекса ничего не доказывает. `ready` объявляется раньше, чем собраны полнотекст
и данные 1С: пока они досчитываются, инструменты отвечают `{"status":"indexing","layer":"fts"}`
или `"layer":"extras"` — это не ошибка, повтори вызов позже.

Проверяй по HTTP: сессия MCP требует `initialize`, затем уведомление
`notifications/initialized` с тем же `Mcp-Session-Id` из заголовка ответа — без него первый
`tools/call` отвергается; ответы приходят как SSE (`data: {...}`), у `initialize` поток
не закрывается — ставь `curl -m 5`; тело с кириллицей передавай файлом (`--data-binary @req.json`).

Три вызова с `repo = "<алиас>"`:

- `health` — `daemon.status: online`, у репозитория `path_status.status: ready`;
- `grep_code` с `pattern` — обращением к объекту расширения и `path_glob` `cfe_<Имя>/**` —
  ответ не пустой, пути начинаются с `cfe_<Имя>/`;
- `bsl_sql` (параметр `sql`): `select extension_name, count(*) from metadata_modules group by
  extension_name` — есть `cf` и каждое расширение с модулями, нет `cf_vendor`. Расширение без
  единого `.bsl` в `metadata_modules` не попадает — это не ошибка индекса.

Не сошлось — разбирайся с причиной (журнал демона, `config.json`, `daemon.toml`); паспорт
под ответ не правь.

## Шаг 7. Отчёт

1. Алиас, путь в `daemon.toml`, что исключено; сколько файлов и модулей по расширениям.
2. Какие файлы проекта и машины изменены; что уже было настроено до запуска.
3. Что не сделано и почему: отказ от автозапуска, заблокированный запуск процессов —
   с готовыми командами для пользователя; индекс ещё не `ready`.
4. Напоминание: `/mcp` → `Reconnect` или перезапуск сессии, чтобы инструменты появились.

## Типичные ошибки

| Ошибка | Как правильно |
|---|---|
| Выдуманные команды `project add`, `--include`, `--exclude` | Регистрация — секция `[[paths]]` в `daemon.toml`; исключения — `config.json` рядом с индексом |
| Регистрация корня проекта или каждого набора отдельно | Один путь на `src` |
| `daemon stop` после правки `daemon.toml` | `daemon reload`; перезапускать — только `serve` |
| Регистрация в демоне до `config.json` | Сначала исключения |
| Нормы работы с индексом в паспорте или отдельный файл правил в проекте | Секция значений в паспорте; нормы — в `mcp.md` шаблона |
| stdio-запись в `.mcp.json` рядом с работающим демоном | HTTP на общий порт |
| Вызов инструмента без `repo` или `[mcp].default_repo` в `daemon.toml` | Без `repo` сервер берёт единственный проект или `default_repo`, общий для всей машины, — ответ придёт по чужому проекту. `repo` передавай всегда, `default_repo` не задавай |
| Вывод «в исходниках этого нет» при `initial_indexing` | Дождаться `ready`, повторить |
| Обновление установщиком поверх работающих процессов | Сначала остановить оба процесса: иначе распаковка молча не проходит, а установщик пишет «Готово» |
| Команда PowerShell пользователю через `!` как есть | `! pwsh -NoProfile -Command '…'` — `!` исполняет bash |
| Автозапуск или установка «чтобы не спрашивать» | Каждая операция вне проекта — по подтверждению |
