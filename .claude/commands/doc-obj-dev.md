## [ИНВАРИАНТНЫЙ АЛГОРИТМ]

### Шаг 1: Определение объектов для анализа

Ниже после этого промпта будут указаны объекты для анализа. Это может быть:
- Путь к файлу или папке
- Имя объекта конфигурации (например: "Документ.РеализацияТоваров", "Обработка.ЗагрузкаДанных")
- Содержимое XML/BSL напрямую
- Несколько объектов сразу

Также могут быть указаны опциональные параметры:
- Подробность: обзорно / стандартно / детально (по умолчанию: стандартно)
- Цель документирования
- Особые акценты (точки расширения, проблемные места, интеграции и т.п.)

**Если объекты не указаны** — спроси пользователя: "Какие объекты 1С нужно документировать? Укажите имена объектов, пути к файлам или вставьте содержимое."

### Шаг 2: Анализ каждого объекта

Если подключены MCP-серверы для работы с 1С (чтение метаданных, навигация по конфигурации), используй их для получения информации об объектах.

Для каждого объекта проанализируй:

1. Тип объекта и его назначение
2. Структура данных: реквизиты, табличные части, типы
3. Формы: список, назначение, ключевые элементы управления
4. Модули:
   - Модуль объекта/менеджера: экспортные процедуры/функции, обработчики событий
   - Модули форм: обработчики команд и событий, клиент-серверное взаимодействие
5. Используемые объекты конфигурации (разделяй типовые и нетиповые с префиксами)
6. Интеграции: HTTP, веб-сервисы, файлы, внешние компоненты
7. Качество кода: закомментированный код, неиспользуемые процедуры, проблемные участки

### Шаг 3: Формулирование выводов

- Описывай только то, о чём есть явная информация
- Предположения явно помечай как предположения
- Не придумывай несуществующие механизмы

### Шаг 4: Написание документации

- Пиши компактно, но технически ёмко
- Адаптируй детализацию под указанный уровень подробности

## [РЕКОМЕНДАЦИИ ПО СТРУКТУРЕ]

Результат — в формате Markdown. Структуру определяй самостоятельно, исходя из типа объекта и найденного функционала.

**Обязательные элементы:**
- Назначение и контекст использования
- Структура данных (реквизиты, табличные части)

**Добавляй разделы по необходимости**, например:
- Формы: список, назначение, ключевые команды
- Модуль объекта: экспортные методы, обработчики событий
- Модуль менеджера: экспортные методы (если есть)
- Модули форм: важные обработчики, клиент-серверное взаимодействие
- Используемые объекты: типовые и нетиповые (с префиксами)
- Интеграции и внешние зависимости
- Качество кода: проблемы, неиспользуемый код, потенциально опасные участки
- Точки расширения (если есть)
- Особенности реализации (если есть что-то нетривиальное)

**Принцип:** добавляй только те разделы, для которых есть содержательная информация. Пустые или формальные разделы не нужны.
