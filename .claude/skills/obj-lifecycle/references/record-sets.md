# obj-lifecycle — Наборы записей регистров (справочник)

> Нормы — в `.claude/rules/1c-rules.md`. Схемы порядка и таблица «куда класть логику» — `../SKILL.md`.

## Паттерн: дом обработчиков — модуль набора записей

У регистра нет «модуля записи»: обработчики событий живут в модуле набора записей, и работают они
с набором целиком, а не с отдельной записью. Внутри `ПередЗаписью` и `ПриЗаписи` `ЭтотОбъект` —
это набор, по которому нужно идти циклом.

```bsl
Процедура ПередЗаписью(Отказ, Замещение)

    Если ОбменДанными.Загрузка Тогда
        Возврат;
    КонецЕсли;

    Для Каждого Запись Из ЭтотОбъект Цикл
        Если Не ЗначениеЗаполнено(Запись.Ответственный) Тогда
            Запись.Ответственный = Пользователи.ТекущийПользователь();
        КонецЕсли;
    КонецЦикла;

КонецПроцедуры
```

Пустой набор — не признак ошибки: запись пустого набора это штатный способ удалить записи
по отбору. Обработчик обязан это переживать.

## Паттерн: запись через `МенеджерЗаписи`

`РегистрСведенийМенеджерЗаписи` работает с данными регистра не напрямую, а через набор записей.
Практических следствий два:

- **Обработчики модуля набора записей отработают** и при записи через менеджер записи. Логика,
  положенная в `ПередЗаписью` или `ПриЗаписи` набора, не обходится переходом на менеджер записи —
  и наоборот, менеджер записи не является способом «записать тихо».
- **Экспортные методы модуля набора записей недоступны** как методы менеджера записи. Если общий
  код нужен обоим путям записи, его место в общем модуле или в модуле менеджера регистра,
  а не в модуле набора записей.

Менеджер записи применим только к регистрам сведений, не подчинённым регистратору.

## Ловушка: при правке существующей записи обработчики вызываются дважды

Менеджер записи не умеет «изменить запись»: он выполняет операцию через два набора записей —
сначала записывает **старый** набор пустым (это и есть удаление прежней записи), затем **новый**
с одной записью. Поэтому при сохранении уже существующей записи регистра `ПередЗаписью`
и `ПриЗаписи` модуля набора записей вызываются **дважды**: первый раз с количеством записей 0,
второй — с количеством 1.

Причина в устройстве: ключевые поля записи (измерения, период) могут измениться, и новый набор
сам по себе не заместил бы старый.

Что из этого следует для кода в модуле набора записей:

- **Обработчик обязан переживать пустой набор** — это не ошибка и не удаление «вообще», а первая
  половина обычного изменения записи.
- **Побочные действия нельзя писать «в лоб»**: логирование, пересчёт, оповещение сработают дважды
  на одно пользовательское действие. Если действие должно быть однократным, привязывай его
  к непустому набору либо выполняй его не здесь.
- **Счётчики и накопление в `ПриЗаписи`** по этой же причине дадут удвоение.

При записи набором записей напрямую (`НаборЗаписей.Записать()`) вызов один.

## Ловушка: движения документа пишутся не вашим кодом

Наборы движений документа, сформированные в `ОбработкаПроведения`, записывает платформа —
и делает это после выхода из обработчика. Обработчики `ПередЗаписью` и `ПриЗаписи` модуля набора
записей при этом тоже отрабатывают, уже внутри транзакции проведения. Значит логика в модуле
набора записей регистра выполняется при каждом проведении каждого документа-регистратора: держи
её дешёвой и не делай в ней запросов к тем же регистрам.
