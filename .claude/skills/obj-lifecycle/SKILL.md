# Жизненный цикл объекта на сервере

> Нормы кода — в `.claude/rules/1c-rules.md` (единственный источник правил).
> Здесь — порядок событий, границы транзакции и практика «что в каком обработчике».

## Приоритеты

1. **Сначала определи, в каком обработчике место логике** — по таблице ниже. Ошибка выбора не ловится
   ни синтаксическим контролем, ни тестом на одной записи: она проявляется на откате транзакции,
   при обмене данными или при программной записи.
2. **Менять реквизиты объекта можно только до записи в базу** — то есть в `ПередЗаписью`
   и раньше. В `ПриЗаписи` объект уже в базе.
3. **Проверяй, в транзакции ты или нет.** Всё, что выполняется в транзакции записи, откатывается
   целиком; всё, что вне, — уже нет.
4. **Не путай модуль формы и модуль объекта.** Одноимённые обработчики — разные события в разных
   модулях, с разными данными и разными последствиями.

## Порядок событий

Схемы даны для интерактивной записи из формы. Заливкой (`*`) отмечено то, что выполняется
**внутри транзакции записи**.

### Запись элемента справочника или документа без проведения

```
клиент  форма    ПередЗаписью
сервер  форма    ОбработкаПроверкиЗаполненияНаСервере
сервер  объект   ОбработкаПроверкиЗаполнения
сервер  форма    ПередЗаписьюНаСервере
сервер  объект * ПередЗаписью
                 ├── ПриУстановкеНовогоКода — только для нового объекта
                 └── запись элемента в базу данных
сервер  объект * ПриЗаписи
сервер  форма  * ПриЗаписиНаСервере
сервер  форма    ПослеЗаписиНаСервере
клиент  форма    ПослеЗаписи
```

### Проведение документа

```
клиент  форма    ПередЗаписью
сервер  форма    ОбработкаПроверкиЗаполненияНаСервере
сервер  объект   ОбработкаПроверкиЗаполнения
сервер  форма    ПередЗаписьюНаСервере
сервер  объект * ПередЗаписью
                 ├── ПриУстановкеНовогоНомера — только для нового документа
                 └── запись документа в базу данных
сервер  объект * ПриЗаписи
сервер  объект * ОбработкаПроведения
                 └── запись сформированных наборов движений
сервер  форма  * ПриЗаписиНаСервере
сервер  форма    ПослеЗаписиНаСервере
клиент  форма    ПослеЗаписи
```

**`ПриЗаписи` вызывается ДО `ОбработкаПроведения`, а не после.** На момент `ПриЗаписи` документ
уже записан, а движений ещё нет — в этом обработчике их анализировать бессмысленно.

### Отмена проведения

Не зеркало проведения, а другая последовательность:

```
клиент  форма    ПередЗаписью
сервер  форма    ПередЗаписьюНаСервере
сервер  объект * ПередЗаписью
сервер  объект * ОбработкаУдаленияПроведения
                 └── запись документа в базу данных
сервер  объект * ПриЗаписи
сервер  форма  * ПриЗаписиНаСервере
сервер  форма    ПослеЗаписиНаСервере
клиент  форма    ПослеЗаписи
```

Два отличия, на которых ошибаются: **проверки заполнения нет вообще** — ни на форме, ни в объекте;
**`ОбработкаУдаленияПроведения` идёт до `ПриЗаписи`**, тогда как при проведении `ОбработкаПроведения`
шла после.

### Запись набора записей регистра

```
клиент  форма    ПередЗаписью
сервер  форма    ОбработкаПроверкиЗаполненияНаСервере
сервер  набор    ОбработкаПроверкиЗаполнения
сервер  форма    ПередЗаписьюНаСервере
сервер  набор  * ПередЗаписью
                 └── запись набора записей в базу данных
сервер  набор  * ПриЗаписи
сервер  форма  * ПриЗаписиНаСервере
сервер  форма    ПослеЗаписиНаСервере
клиент  форма    ПослеЗаписи
```

Подробности по наборам записей и `МенеджерЗаписи` — `references/record-sets.md`.

## Куда класть логику

| Обработчик | Для чего он | Чего в нём делать нельзя |
|---|---|---|
| `ОбработкаЗаполнения` | Заполнение нового объекта по данным основания; запрет ввода на основании неподходящего объекта | Считать, что он отработает при любом создании объекта |
| `ОбработкаПроверкиЗаполнения` | Проверки корректности заполнения реквизитов до записи | Проверки целостности движений и связанных данных: обработчик вне транзакции и вызывается не при каждой записи |
| `ПередЗаписью` | Дозаполнение реквизитов, проверки в транзакции, сравнение со «старым» состоянием в базе | Считать, что объект уже записан |
| `ПриУстановкеНовогоНомера`, `ПриУстановкеНовогоКода` | Задать префикс автонумерации или свою нумерацию через `СтандартнаяОбработка = Ложь` | Класть сюда бизнес-логику: обработчик вызывается только при получении номера новым объектом |
| `ПриЗаписи` | Запись связанных данных в другие объекты | Менять реквизиты самого объекта — он уже в базе |
| `ОбработкаПроведения` | Формирование движений | Записывать наборы движений вручную; анализировать движения, ещё не сформированные этим же обработчиком |
| `ОбработкаУдаленияПроведения` | Действия при отмене проведения, ручная чистка движений | Рассчитывать на проверку заполнения — её не будет |
| `ПередУдалением` | Действия до удаления объекта: чистка ссылок на него | Считать, что связанные данные удалятся сами |

Все обработчики этой таблицы, кроме `ОбработкаЗаполнения` и `ОбработкаПроверкиЗаполнения`,
выполняются в транзакции записи и обязаны начинаться с проверки `ОбменДанными.Загрузка` —
норма в `1c-rules.md`.

## Чек-лист жизненного цикла

Дополняет мастер-чек-лист из `1c-rules.md`, не заменяет его.

- [ ] Логика размещена в обработчике по таблице «Куда класть логику», а не в первом подходящем
- [ ] Реквизиты объекта меняются не позже `ПередЗаписью`
- [ ] Обработчики в транзакции записи начинаются с проверки `ОбменДанными.Загрузка`
- [ ] Проверка, которой нужны движения или связанные данные, не оставлена в `ОбработкаПроверкиЗаполнения`
- [ ] Логика, обязательная при любой записи, не оставлена в `ОбработкаПроверкиЗаполнения`: при программной записи он не вызывается
- [ ] В `ОбработкаПроведения` наборы движений не записываются вручную
- [ ] Для отмены проведения не предполагается ни проверка заполнения, ни порядок «как при проведении»
- [ ] Обработчик, устанавливающий `Отказ`, сообщает пользователю причину
- [ ] Долгие операции, обращения к внешним системам и диалоги не выполняются внутри транзакции записи
