# Чтение журнала платформой: COM и MCP

Свой парсер отвечает на вопрос «цел ли файл», но не на вопрос «как его прочитает 1С». Последнее
проверяется только платформой — через внешнее соединение (COM) или через MCP-сервер базы.

## COM (`V83.COMConnector`)

- Коннектор должен быть зарегистрирован и **той же версии**, что платформа файловой базы или сервер
  кластера. Проверка: `HKCR\V83.COMConnector` и путь `InprocServer32` у его CLSID.
  Регистрировать (`regsvr32`) — изменение системы, только с разрешения пользователя.
- Строка соединения: `File="<каталог>";Usr="...";Pwd="...";` или `Srvr="<сервер>";Ref="<база>";Usr=...;`.
  Аргументом `cscript` передавать без внутренних кавычек (`File=C:\Bases\Demo;Usr=Администратор;`):
  `cscript` не понимает `\"`, обратная косая попадает в значение — «Неверно указан пользователь или пароль».
  Неверный логин: «Неверное имя пользователя или пароль»; у демо-БСП — `Администратор` без пароля.
- Подключение — это сеанс: база запишет в свой журнал вход, а файловая база при необходимости создаст
  новый `.lgp` и допишет `.lgf`.

### Чем вызывать

| Чем | Итог |
|---|---|
| PowerShell (`New-Object -ComObject`) | Ненадежно: значения обертываются в PSObject, 1С отвечает `DISP_E_TYPEMISMATCH`, свойства строк таблицы приходят `$null`. Не использовать |
| VBScript (`cscript`) | Работает с английскими именами. **Кириллица в идентификаторах запрещена** (`c.Обработки` — синтаксическая ошибка). Файл `.vbs` хранить в UTF-16 LE, иначе литералы с кириллицей портятся |
| JScript (`cscript //E:jscript`) | Лучший вариант: русские имена через скобки `c["ЖурналРегистрации"]["ПрочитатьСобытияЖурналаРегистрации"](...)`, файл в UTF-16 LE |

Вывод `cscript //U` — UTF-16; читать `[IO.File]::ReadAllText(path, [Text.Encoding]::Unicode)`.
Запускать через `Start-Process cscript.exe -ArgumentList "..." -RedirectStandardOutput <файл> -Wait -NoNewWindow`.

### Особенности объектной модели через COM

- `UnloadEventLog(таблица, отбор, колонки)` (= `ВыгрузитьЖурналРегистрации`). Ключи отбора по-английски
  (`StartDate`, `EndDate`, `Event`, `Level`) работают; уровень — `c.EventLogLevel.Error`.
- Колонки результирующей таблицы приходят с русскими именами; `row.Data` из VBScript не работает —
  брать `row.Get(индексКолонки)`, индекс искать перебором `t.Columns.Get(j).Name`.
  `Columns.Find` возвращает Неопределено, а не `Nothing` — `Set x = ...Find()` падает.
- `ТипЗнч`/`TypeOf` через COM недоступен. Тип: `IsObject(v)` → объект 1С, его тип — `c.String(v)`
  (для структуры вернет «Структура»); иначе — примитив, `TypeName(v)` VBScript.
- Общий модуль доступен из COM, только если у него стоит флаг «Внешнее соединение»
  (`ЖурналРегистрации` в БСП 3.1 — стоит; проверять по XML модуля: `<ExternalConnection>true`).
- Временное хранилище: `c.PutToTempStorage(null, c.NewObject("УникальныйИдентификатор"))`,
  результат — `c.GetFromTempStorage(адрес)`.

## MCP-сервер базы (1c_mcp)

Если база подключена к проекту через MCP (`.mcp.json`, публикация `http://<сервер>/<публикация>/hs/mcp/`):
- `eventlog_filter_values` / `eventlog_query` — журнал с отборами (до 500 записей за вызов).
- `execute_code` — произвольный код на сервере; результат через переменную `__Возврат`.
  Код исполняется через `Выполнить()`: **объявлять процедуры и функции нельзя** — только операторы,
  повторяющиеся куски оформлять циклом по массиву структур.
  Когда нужно подтверждение пользователя — по нормам `.claude/rules/mcp.md` и режиму базы в `CLAUDE.md`.
- Долгий вызов (выгрузка всего журнала, сотни тысяч строк) идет минуты; клиент может увести ожидание
  в фон — это не фоновое задание 1С, а один долгий HTTP-запрос.
- Проверка доступности сервиса без клиента MCP: POST JSON-RPC `initialize` на адрес публикации
  (GET дает 405 — это нормально).

Форма «Журнал регистрации» БСП вызывает `ПрочитатьСобытияЖурналаРегистрации` через
`ДлительныеОперации.ВыполнитьВФоне`; прямой вызов в сеансе COM или MCP выполняет тот же код,
отличается только место запуска — для проверки «падает ли БСП» этого достаточно.
