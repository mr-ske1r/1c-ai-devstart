# Ремонт журнала регистрации 1С (старый формат)

Журнал старого формата — файлы в каталоге `1Cv8Log`: словарь `1Cv8.lgf`, записи `*.lgp` (текст,
номера вместо имен) и индекс `*.lgx` (байтовые смещения в `.lgp`).
Все, что ниже, следует из этого устройства: записи без своего словаря бессмысленны, а индекс после
любой правки `.lgp` врет. Формат подробно — `references/format.md`.

## Главные правила и почему

- **Исходники только читать, результат писать в новый файл.** Файл журнала — единственная копия
  истории базы; ошибка в фильтре на месте ее уничтожит.
- **`1Cv8.lgf` не менять и не подменять чужим.** Номера в `.lgp` указывают в словарь своей базы.
  Чужой словарь (даже от копии этой же базы) превращает записи в другие события — так появляется
  «Повреждение журнала» и падение БСП. Более свежий `.lgf` той же базы совместим: он только дописывается.
- **`.lgx` к измененному `.lgp` не прикладывать.** Платформа построит новый сама.
- **Не смешивать в одном `1Cv8Log` файлы `.lgp`, записанные с разными словарями.**
- **Ничего не удалять у пользователя — переносить в резервную папку.** Удалять — его решение после
  нескольких дней нормальной работы.
- **Проверять платформой, а не только своим парсером.** Парсер говорит «файл цел», платформа и код БСП —
  «журнал читается». Это разные утверждения.
- **Выдержки из журнала не выносить во внешние сервисы и модели.** В журнале персональные данные
  (имена пользователей, представления документов, комментарии ошибок) — показывай их только пользователю.
- **Запуск платформы, остановка кластера, подмена журнала чужой базы (даже демо) и любые действия
  на сервере пользователя — только с его явного разрешения на конкретную операцию.** Перед подменой
  журнала стенда сохранить его копию и сверить хеши; после — вернуть и сверить снова. Вызовы MCP-сервера
  базы — по режимам из `.claude/rules/mcp.md`.

## Паттерн: сначала выбрать путь

| Ситуация | Путь |
|---|---|
| Историю до некоторой даты можно потерять или сохранить отдельным файлом | Штатное сокращение по дате (ниже) — фильтр не нужен |
| Мусор размазан по всему периоду, история нужна | Фильтрация этим скиллом |
| Источник мусора еще пишет (ошибка обновления, обработчик в цикле) | Сначала устранить источник, иначе журнал вырастет снова |
| Журнал сбоит после подмены файлов или чужой «обрезки» | Сразу раздел «Если журнал сбоит» — резать нечего |
| Просят перейти на формат SQLite (`.lgd`) | С 8.3.22 формат SQLite для журнала не выбирается; возможна только обратная конвертация `.lgd` → последовательный. Против разрастания — деление по периодам |

Штатное сокращение режет **только по дате**: удаляет все записи до указанного дня, по желанию сохраняя
их в файл. Конфигуратор: «Администрирование → Настройки журнала регистрации → Сократить»; пакетный
режим: `1cv8.exe DESIGNER ... /ReduceEventLogSize <ГГГГ-ММ-ДД> -saveAs <файл>` (каталоги в пути файла
должны существовать). По событию или тексту комментария штатно резать нельзя — для этого фильтр ниже.

## Порядок работы фильтром

### 1. Факты, прежде чем резать
- Список файлов `1Cv8Log` с размерами, **временем создания** и изменения. Лишний `.lgp` с чужим временем
  создания — первый подозреваемый.
- Вариант базы (файловая или клиент-серверная), версия платформы, есть ли у базы MCP-сервер в проекте
  (тогда проверка через него, см. `references/platform-access.md`).
- Где писать результат: нужен диск с запасом не меньше размера исходника — сколько останется, до Stats
  не узнать.
- Выводы о причине сбоя — только после того, как увидел сами файлы. Гипотеза без списка файлов с датами
  создания уводит в сторону.

### 2. Статистика
```powershell
scripts\Filter-1CLog.ps1 -Mode Stats -Lgp <исходный.lgp> -Lgf <1Cv8.lgf> -OutDir <каталог отчетов>
```
`stats.csv` — записи и мегабайты по (событие, важность, статус транзакции). Мусор виден сразу:
одно событие с десятками гигабайт. Решение, что резать, принимает пользователь — покажи ему цифры
и пример записей (`scripts\Grep-LgpRecords.ps1`).

Типичный мусор — бесконечный повтор ошибки обработчика: `W`/`E`-запись с одинаковым началом
комментария плюс пустая откатанная транзакция (`_$Transaction$_.Begin` + `_$Transaction$_.Rollback`)
того же соединения прямо перед ней. Удалять записи по началу комментария, а не все записи события:
то же событие бывает и полезным.

### 3. Самопроверка фильтра
Без правила (`-DropEvent` не задан) режим Filter обязан дать файл, совпадающий с началом исходника
байт в байт. Это ловит ошибки на стыках блоков чтения и порчу заголовка. После любой правки скрипта — повторить.
```powershell
scripts\Filter-1CLog.ps1 -Mode Filter -Lgp <исходный.lgp> -Lgf <1Cv8.lgf> -OutDir <пусто>\dry -MaxBytes 200MB
scripts\Test-LgpPrefix.ps1 -Source <исходный.lgp> -Copy <пусто>\dry\<имя>.lgp
```

### 4. Фильтрация
```powershell
scripts\Filter-1CLog.ps1 -Mode Filter -Lgp <исходный.lgp> -Lgf <1Cv8.lgf> `
  -OutDir <...>\1Cv8Log -ReportDir <...> `
  -DropEvent '<имя события из stats.csv>' -DropSeverity W -CommentPrefix '<начало комментария>' -LinkEmptyRollback
```
Затем контроль: Stats по результату — 0 записей по правилу, «оставлено» совпадает, нарушений структуры 0.
`removed-sample.txt` — первые удаленные записи, показать пользователю. Скорость 60–200 МБ/с; 100 ГБ —
около 10 минут.

### 5. Проверка платформой
Стенд — пустая файловая база той же версии или демо-база с БСП (только с разрешения).
Подробно — `references/diagnostics.md`, раздел «Проверка на стенде».
- `scripts\Read-1CLog.vbs` — все «Отказы в доступе» со структурой в «Данных», ошибки и «Повреждение
  журнала», помесячный счет записей (сверить с отчетом фильтра).
- `scripts\Test-BspEventLog.js` — код БСП `ЖурналРегистрации.ПрочитатьСобытияЖурналаРегистрации`
  на типовых отборах и на днях, где падала форма.
Экземпляр, подложенный стенду, стенд дополнит своими записями — для рабочей базы собрать файл заново.

### 6. Подселение (делает пользователь)
Дай ему короткую инструкцию:
1. Клиент-серверная база — остановить кластер (службу агента сервера 1С): это отключит все базы
   кластера, окно согласовать заранее. Замена журнала при работающем кластере не гарантирована,
   даже если сеансы базы завершены и заблокированы. Файловая база — завершить все сеансы.
2. Скопировать весь `1Cv8Log` в резервную папку, сверить размеры.
3. Убрать из `1Cv8Log` только заменяемые `.lgp` и `.lgx`; положить новый `.lgp`, сверить размер.
   `1Cv8.lgf` и остальные `.lgp`/`.lgx` базы не трогать.
4. Запустить, открыть журнал (индекс строится заново, на большом файле — минуты), убедиться,
   что пишутся свежие записи.

И на будущее: включить деление журнала по периодам с таким периодом, чтобы один файл был не больше
~100 МБ (настройка журнала регистрации в конфигураторе или в режиме предприятия; в сетевом режиме
сохраняется, только когда в базе никого, кроме администратора), и устранить источник мусора.

## Если журнал сбоит
`references/diagnostics.md`: падение БСП на `.Свойство("Право")` и «Повреждение журнала» почти всегда
означают чужие записи в `1Cv8Log` (лишний `.lgp`, подмененный словарь), а не порчу очищенного файла.
Первый быстрый признак без платформы — Stats каждого `.lgp` с текущим словарем: у события
`_$Transaction$_.Begin`/`Commit`/`Rollback` статус `N` означает, что файл записан с другим словарем.
Затем искать виновные записи платформой, по дате и сеансу находить файл, в котором они лежат.

## Скрипты

| Скрипт | Что делает |
|---|---|
| `scripts/Filter-1CLog.ps1` | Stats и Filter, правило удаления параметрами |
| `scripts/Test-LgpPrefix.ps1` | Самопроверка: файл холостого прогона совпадает с началом исходника и кончается на границе записи |
| `scripts/Diag-Lgp.ps1` | Структурная диагностика: число полей, даты назад, номера вне словаря, выписка окрестности даты |
| `scripts/Grep-LgpRecords.ps1` | Выписать записи по префиксу даты и номеру события |
| `scripts/Read-1CLog.vbs` | Чтение журнала платформой через COM (UTF-16, `cscript //U`) |
| `scripts/Test-BspEventLog.js` | Прогон кода БСП журнала через COM (UTF-16, `cscript //U //E:jscript`) |

PowerShell-скрипты требуют PowerShell 7 (`pwsh`), ставить ничего больше не нужно: C# встроен в скрипт.
Все потоковые — файл любого размера читается блоками, память не растет. Python не нужен (на машинах 1С
его часто нет, а `python.exe` бывает заглушкой Microsoft Store).
