## Паттерн: обработчики событий формы — порядок и назначение

**Почему:** Платформа 1С вызывает обработчики событий в определённом порядке. Понимание порядка критически важно — код в неправильном обработчике либо не выполнится, либо выполнится с устаревшими данными.

### Порядок событий при открытии формы

```
1. ПриСозданииНаСервере     — форма создаётся на сервере, данные загружены
2. ПриОткрытии              — клиентский код, выполняется ПЕРЕД показом формы
```

### Порядок событий при записи

```
1. ПередЗаписью              — клиент: можно отменить запись (Отказ = Истина)
2. ОбработкаПроверкиЗаполненияНаСервере — сервер: проверка заполнения на стороне формы
   ↓ дальше отрабатывает ОбработкаПроверкиЗаполнения модуля объекта
3. ПередЗаписьюНаСервере     — сервер: последняя точка формы до транзакции записи
   ↓ дальше открывается транзакция и отрабатывает вся цепочка модуля объекта:
     ПередЗаписью → запись в базу → ПриЗаписи → ОбработкаПроведения
4. ПриЗаписиНаСервере        — сервер: логика после записи объекта, ещё в транзакции
5. ПослеЗаписиНаСервере      — сервер: обновление формы после записи, вне транзакции
6. ПослеЗаписи               — клиент: оповещение об успешной записи
```

Между шагами 3 и 4 работает модуль объекта, а не форма: там своя последовательность, свои
правила и своя транзакция. Порядок объектных обработчиков, что можно менять в каждом
и чем отличается отмена проведения — скилл `obj-lifecycle`.

### Пример: разнесение логики по обработчикам

```bsl
// ПриСозданииНаСервере — инициализация формы
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    
    Если Параметры.Свойство("ЗначенияЗаполнения") Тогда
        ЗаполнитьЗначенияСвойств(Объект, Параметры.ЗначенияЗаполнения);
    КонецЕсли;
    
    // Условная видимость элементов
    Элементы.ГруппаСклад.Видимость = (Объект.ВидОперации <> 
        Перечисления.ВидыОпераций.Услуга);
    
    // Заполнение списков выбора
    ОбновитьСписокВыбораДоговоров();
    
КонецПроцедуры

// ПередЗаписьюНаКлиенте — проверки до отправки данных на сервер
&НаКлиенте
Процедура ПередЗаписью(Отказ, ПараметрыЗаписи)
    
    Если Объект.СуммаДокумента < 0 Тогда
        Отказ = Истина;
        ОбщегоНазначенияКлиент.СообщитьПользователю(
            НСтр("ru = 'Сумма документа не может быть отрицательной.'"));
    КонецЕсли;
    
КонецПроцедуры

// ПриЗаписиНаСервере — действия после записи объекта, но в той же транзакции
&НаСервере
Процедура ПриЗаписиНаСервере(Отказ, ТекущийОбъект, ПараметрыЗаписи)
    
    // ТекущийОбъект — это настоящий объект (не данные формы!)
    // Можно вызывать методы модуля объекта, писать в регистры
    
    Если ТекущийОбъект.ЭтоНовый() Тогда
        // Дополнительная инициализация при первой записи
    КонецЕсли;
    
КонецПроцедуры

// ПослеЗаписи — уведомления на клиенте
&НаКлиенте
Процедура ПослеЗаписи(ПараметрыЗаписи)
    // Оповещаем другие открытые формы об изменении
    Оповестить("Запись_РеализацияТоваровУслуг", 
        Новый Структура("Ссылка", Объект.Ссылка), ЭтотОбъект);
КонецПроцедуры
```

### Интерактивная проверка при `ПередЗаписью` через обработчик оповещения

`ПоказатьВопрос()` с `ОписаниеОповещения` — допустимый немодальный вариант для проектов, где выбран стиль `Показать* + ОписаниеОповещения`. В отменяемом событии сначала синхронно установи `Отказ = Истина`, а после ответа пользователя явно повтори действие. Флаг модуля формы защищает от повторного показа вопроса.

Ниже завершённый вариант для сценария, в котором после подтверждения требуется именно обычная запись формы:

```bsl
Перем ПодтверждениеСуммыПолучено;

&НаКлиенте
Процедура ПередЗаписью(Отказ, ПараметрыЗаписи)

    Если ПодтверждениеСуммыПолучено Тогда
        ПодтверждениеСуммыПолучено = Ложь;
        Возврат;
    КонецЕсли;

    ПорогПодтверждения = 1000000;
    Если Объект.СуммаДокумента <= ПорогПодтверждения Тогда
        Возврат;
    КонецЕсли;

    Отказ = Истина;
    Оповещение = Новый ОписаниеОповещения(
        "ПослеПодтвержденияСуммы",
        ЭтотОбъект);
    ПоказатьВопрос(
        Оповещение,
        НСтр("ru = 'Сумма документа превышает 1 000 000. Продолжить?'"),
        РежимДиалогаВопрос.ДаНет);

КонецПроцедуры

&НаКлиенте
Процедура ПослеПодтвержденияСуммы(РезультатВопроса, ДополнительныеПараметры) Экспорт

    Если РезультатВопроса <> КодВозвратаДиалога.Да Тогда
        Возврат;
    КонецЕсли;

    ПодтверждениеСуммыПолучено = Истина;
    Записать();

КонецПроцедуры
```

Обработчик `ПередЗаписью` не позволяет надёжно определить, какую стандартную команду выбрал пользователь: `Записать` или `Записать и закрыть`. Поэтому приведённый пример не применяй без изменения в форме, где доступны оба сценария: после подтверждения нельзя молча заменять `Записать и закрыть` обычной записью. Если дальнейшее действие различается, перенеси подтверждение в соответствующие команды формы либо явно запроси требуемое действие и повтори именно его.

## Паттерн: привязка обработчика к событию

**Почему:** Процедура в модуле формы не становится обработчиком только из-за совпадения имени с событием. Она должна быть НАЗНАЧЕНА событию формы, команды или элемента — иначе платформа её не вызовет, а код будет выглядеть рабочим.

- Убедись, что новая процедура-обработчик назначена соответствующему событию (палитра свойств элемента/формы/команды).
- Привязка хранится в `Form.xml`, а его **напрямую не редактируем** (политика шаблона). Если обработчик не привязан — сообщи пользователю, какое событие и какую процедуру связать через Конфигуратор/EDT. После штатной правки перечитай исходники формы и проверь привязку.

### Программное подключение — префикс Подключаемый_ (std#492)

Если обработчик назначается программно через `УстановитьДействие`, у процедуры должен быть префикс `Подключаемый_` — это отличает динамически подключённые процедуры при поиске неиспользуемого кода. Префикс нужен ТОЛЬКО для программного подключения; обработчики, назначенные в метаданных формы, его не требуют. Источник: [std#492](https://v8std.ru/std/492/).

```bsl
&НаСервере
Процедура УстановитьОбработчикиЭлементов()
    Элементы.Комментарий.УстановитьДействие("ПриИзменении", "Подключаемый_КомментарийПриИзменении");
КонецПроцедуры

&НаКлиенте
Процедура Подключаемый_КомментарийПриИзменении(Элемент)
    // ...
КонецПроцедуры
```

## Паттерн: выбор стиля клиентской асинхронности

Стиль задаётся в «Настройках проекта» файла `CLAUDE.md`:

- `Показать* + ОписаниеОповещения` — продолжение выполняется в отдельной экспортной процедуре;
- `Асинх/Ждать` — код продолжает выполняться с точки `Ждать`; этот вариант доступен на платформе версии 8.3.18 или выше (реализовано в 8.3.18.1128). **Режим совместимости конфигурации на доступность не влияет** — проверено экспериментом: на платформе 8.3.27.1936 в базе с режимом совместимости 8.3.12 работают и синтаксис `Асинх`/`Ждать`, и методы `ВопросАсинх`, `ПредупреждениеАсинх`. Учти при этом, что статический анализ берёт режим совместимости за целевую версию платформы и может пометить такой код как недоступный (`bslls:UnavailableMemberCall`) — это ложное срабатывание анализатора, а не запрет платформы.

Оба варианта немодальные. Выбор меняет способ записи продолжения, но не превращает серверный код в параллельный и не заменяет фоновые задания для длительных операций. Если используемый программный интерфейс поддерживает только один вариант, следуй его контракту.

### Вариант 1 — Показать* + ОписаниеОповещения

```bsl
// Команда удаления — с подтверждением через асинхронный диалог
&НаКлиенте
Процедура УдалитьСтрокуТоваров(Команда)
    
    Если Элементы.Товары.ТекущаяСтрока = Неопределено Тогда
        Возврат;
    КонецЕсли;
    
    // Асинхронный вопрос с обработчиком оповещения
    ПоказатьВопрос(
        Новый ОписаниеОповещения("ПослеПодтвержденияУдаления", ЭтотОбъект),
        НСтр("ru = 'Удалить выбранную строку?'"),
        РежимДиалогаВопрос.ДаНет,
        ,
        КодВозвратаДиалога.Нет);  // По умолчанию — «Нет»
    
КонецПроцедуры

// Обработчик вызывается после ответа пользователя
&НаКлиенте
Процедура ПослеПодтвержденияУдаления(Результат, ДополнительныеПараметры) Экспорт
    
    Если Результат = КодВозвратаДиалога.Да Тогда
        Объект.Товары.Удалить(Элементы.Товары.ТекущаяСтрока);
    КонецЕсли;
    
КонецПроцедуры
```

### Вариант 2 — Асинх/Ждать

```bsl
&НаКлиенте
Асинх Процедура УдалитьСтрокуТоваров(Команда)

    Если Элементы.Товары.ТекущаяСтрока = Неопределено Тогда
        Возврат;
    КонецЕсли;

    Результат = Ждать ВопросАсинх(
        НСтр("ru = 'Удалить выбранную строку?'"),
        РежимДиалогаВопрос.ДаНет,
        ,
        КодВозвратаДиалога.Нет);

    Если Результат = КодВозвратаДиалога.Да Тогда
        Объект.Товары.Удалить(Элементы.Товары.ТекущаяСтрока);
    КонецЕсли;

КонецПроцедуры
```

Обработчики команд можно объявлять `Асинх`: платформа вызывает их как точки входа, а код после `Ждать` продолжится после завершения операции.

### Неправильно — модальный вызов

```bsl
// ❌ ПЛОХО: модальный вызов — не работает в веб-клиенте
&НаКлиенте
Процедура УдалитьСтрокуТоваров(Команда)
    
    Ответ = Вопрос("Удалить строку?", РежимДиалогаВопрос.ДаНет); // МОДАЛЬНЫЙ — ЗАПРЕЩЕНО!
    Если Ответ = КодВозвратаДиалога.Да Тогда
        Объект.Товары.Удалить(Элементы.Товары.ТекущаяСтрока);
    КонецЕсли;
    
КонецПроцедуры
```

## Паттерн: открытие форм и обработка результата

**Почему:** Правильная передача параметров при открытии формы и обработка результата закрытия — основа навигации в 1С. Неправильная работа с параметрами приводит к потере данных и некорректному поведению.

Обработчик результата закрытия передаётся в `ОткрытьФорму()` через `ОписаниеОповещения` по контракту этого API; настройка стиля проекта его не заменяет.

### Открытие формы с параметрами

```bsl
&НаКлиенте
Процедура ОткрытьФормуПодбораТоваров(Команда)
    
    ПараметрыФормы = Новый Структура;
    ПараметрыФормы.Вставить("Организация", Объект.Организация);
    ПараметрыФормы.Вставить("Склад", Объект.Склад);
    ПараметрыФормы.Вставить("Дата", Объект.Дата);
    ПараметрыФормы.Вставить("МножественныйВыбор", Истина);
    
    ОткрытьФорму("Обработка.ПодборТоваров.Форма",
        ПараметрыФормы,
        ЭтотОбъект,                     // Владелец
        ,                                 // Уникальность
        ,                                 // Окно
        ,                                 // НавигационнаяСсылка
        Новый ОписаниеОповещения("ПослеПодбораТоваров", ЭтотОбъект));
    
КонецПроцедуры

// Обработка результата закрытия формы подбора
&НаКлиенте
Процедура ПослеПодбораТоваров(РезультатПодбора, ДополнительныеПараметры) Экспорт
    
    Если РезультатПодбора = Неопределено Тогда
        Возврат; // Пользователь закрыл форму без выбора
    КонецЕсли;
    
    // РезультатПодбора — массив структур с данными товаров
    Для Каждого ДанныеТовара Из РезультатПодбора Цикл
        НоваяСтрока = Объект.Товары.Добавить();
        ЗаполнитьЗначенияСвойств(НоваяСтрока, ДанныеТовара);
    КонецЦикла;
    
    Модифицированность = Истина; // Помечаем форму как изменённую
    
КонецПроцедуры
```

## Паттерн: механика и ловушки Асинх/Ждать

`Асинх/Ждать` — клиентская форма работы с уже существующей асинхронностью платформы:

- оператор `Ждать` допустим только внутри `Асинх`-процедуры или функции;
- `Асинх Функция` возвращает `Обещание`, даже если результат ещё не получен;
- параметры `Асинх`-методов передаются по значению;
- `Ждать` возвращает результат обещания или выбрасывает сохранённое в нём исключение;
- `Асинх Процедура` не возвращает обещание вызывающему коду: необработанное исключение показывается пользователю, но вызывающий код не может его перехватить.

### Риск — вызов Асинх Функции без Ждать

```bsl
&НаКлиенте
Процедура КомандаВыполнить(Команда)
    ВыполнитьАсинхронно(); // обещание проигнорировано: вызывающий код не получит результат и исключение
КонецПроцедуры

&НаКлиенте
Асинх Функция ВыполнитьАсинхронно()
    Ждать ПредупреждениеАсинх("Возможна ошибка");
    ВызватьИсключение "Что-то пошло не так";
КонецФункции
```

### Ждать — когда вызывающему коду нужны результат или обработка исключения

```bsl
&НаКлиенте
Асинх Процедура КомандаВыполнить(Команда)
    Попытка
        Ждать ВыполнитьАсинхронно();
    Исключение
        ОбщегоНазначенияКлиент.СообщитьПользователю(
            ОбработкаОшибок.КраткоеПредставлениеОшибки(ИнформацияОбОшибке()));
    КонецПопытки;
КонецПроцедуры
```

Вызов асинхронной функции без `Ждать` синтаксически возможен. Используй его только когда результат и обработка ошибки действительно не нужны; для прикладных операций это редкий осознанный сценарий.

### Ловушка отменяемых событий — Асинх-обработчик не изменит Отказ

Все параметры `Асинх`-процедур и функций передаются по значению. Поэтому `Отказ`, изменённый внутри `Асинх`-обработчика, не повлияет на параметр события даже до первого `Ждать`; после `Ждать` стандартная обработка события к тому же уже продолжится.

```bsl
// ПЛОХО: Асинх-обработчик получает Отказ по значению и не может отменить событие
&НаКлиенте
Асинх Процедура ПередЗакрытием(Отказ, ЗавершениеРаботы, ТекстПредупреждения, СтандартнаяОбработка)
    Результат = Ждать ВопросАсинх("Закрыть без сохранения?", РежимДиалогаВопрос.ДаНет);
    Если Результат <> КодВозвратаДиалога.Да Тогда
        Отказ = Истина; // не сработает: параметр передан по значению
    КонецЕсли;
КонецПроцедуры
```

Обработчик отменяемого события (`ПередЗакрытием`, `ПередЗаписью`) оставляй обычной процедурой: синхронно установи `Отказ = Истина`, затем запусти отдельное продолжение, получи подтверждение и повтори действие явно. Не объявляй сам обработчик `Асинх`: его параметры передаются по значению. Та же схема применяется с обработчиком оповещения.

```bsl
Перем ЗакрытиеПодтверждено;

&НаКлиенте
Процедура ПередЗакрытием(Отказ, ЗавершениеРаботы, ТекстПредупреждения, СтандартнаяОбработка)

    Если ЗакрытиеПодтверждено Тогда
        Возврат;
    КонецЕсли;

    Отказ = Истина;
    ПодтвердитьЗакрытие();

КонецПроцедуры

&НаКлиенте
Асинх Процедура ПодтвердитьЗакрытие()

    Результат = Ждать ВопросАсинх(
        НСтр("ru = 'Закрыть без сохранения?'"),
        РежимДиалогаВопрос.ДаНет);

    Если Результат = КодВозвратаДиалога.Да Тогда
        ЗакрытиеПодтверждено = Истина;
        ЭтаФорма.Закрыть();
    КонецЕсли;

КонецПроцедуры
```

## Паттерн: оповещения между формами

**Почему:** Когда пользователь изменяет данные в одной форме, другие открытые формы должны обновиться. Механизм `Оповестить()` / `ОбработкаОповещения()` — стандартный способ межформенного взаимодействия.

### Паттерн: отправка оповещения после записи

```bsl
// Форма документа — после записи
&НаКлиенте
```
