## Паттерн: программное добавление реквизита и элемента формы

**Почему:** типовую форму дорабатывают кодом, а не заимствованием — норма в `.claude/rules/1c-rules.md`
(### Формы). Три артефакта, которые легко перепутать в задаче «добавь поле на форму»:

| Артефакт | Чем создаётся |
|---|---|
| Реквизит объекта (документа, справочника) | Конфигуратор или EDT — кодом не создаётся |
| Реквизит формы | `ИзменитьРеквизиты()` |
| Элемент формы | `Элементы.Добавить()` |

Порядок обязателен: сначала реквизит, потом элемент на него.

**Сначала посмотри, как программная модификация уже сделана в этом модуле формы.** Если там принят
другой подход — продолжай в нём, а не разводи два стиля в одном модуле: читать и сопровождать
модуль, где половина элементов создана одним способом, а половина другим, заметно дороже. Подход
принят не тобой — не переучивай модуль попутно с задачей, а если считаешь его неудачным, скажи
об этом пользователю отдельно.

**Как подключается вход.** В расширении `ПриСозданииНаСервере` перехватывается **привязкой
к событию формы** с типом «После», а не директивой — норма в `.claude/rules/1c-rules.md`
(### Архитектура), механизм и вид записи в `Form.xml` — в скилле `config-modification`
(«Паттерн: перехват события формы»). Поэтому у процедуры ниже стоит только директива
компиляции: тип вызова задан в свойствах формы, а не в модуле.

```bsl
&НаСервере
Процедура Расш1_ПриСозданииНаСервереПосле(Отказ, СтандартнаяОбработка)

	Расш1_ДобавитьПолеВипЗаказ();

КонецПроцедуры

&НаСервере
Процедура Расш1_ДобавитьПолеВипЗаказ()

	Добавляемые = Новый Массив;
	Добавляемые.Добавить(Новый РеквизитФормы("Расш1_ВипЗаказ",
		Новый ОписаниеТипов("Булево"), , НСтр("ru = 'ВИП-заказ'")));
	Добавляемые.Добавить(Новый РеквизитФормы("Расш1_Комментарий",
		ОбщегоНазначения.ОписаниеТипаСтрока(100), , НСтр("ru = 'Комментарий ВИП'")));
	ИзменитьРеквизиты(Добавляемые);

	Поле = Элементы.Добавить("Расш1_ВипЗаказ", Тип("ПолеФормы"), Элементы.ГруппаШапка);
	Поле.ПутьКДанным = "Расш1_ВипЗаказ";
	Поле.Вид = ВидПоляФормы.ПолеФлажка;

КонецПроцедуры
```

Связь элемента с реквизитом задаётся свойством `ПутьКДанным` — оно принадлежит **элементу**,
а не реквизиту.

Размещение задаётся третьим параметром — родителем. Без него элемент попадает в корень формы,
то есть в конец:

```bsl
Элементы.Добавить(Имя, Тип, Родитель)
Элементы.Вставить(Имя, Тип, Родитель, ЭлементПередКоторымВставить)
```

Программное построение медленнее и накладнее, чем форма из конфигуратора. Это инструмент
точечной доработки типовой формы, а не способ собирать интерфейс целиком.

### Что можно создать

| Тип элемента | Чем задаётся вид |
|---|---|
| `ПолеФормы` | `Вид`: `ПолеВвода`, `ПолеФлажка`, `ПолеНадписи`, `ПолеИндикатора`, `ПолеПолосыРегулирования`, `ПолеПереключателя`, `ПолеКартинки`, `ПолеТекстовогоДокумента` |
| `ГруппаФормы` | `Вид`: `ОбычнаяГруппа`, `Страницы`, `Страница`, `Подменю`, `ГруппаКнопок`; расположение — `Группировка`: `ГоризонтальнаяВсегда`, `Вертикальная` |
| `ТаблицаФормы` | `ПутьКДанным` — табличная часть |
| `КнопкаФормы` | `ИмяКоманды` |
| `ДекорацияФормы` | `Вид`: `Надпись`, `Картинка` |

Закладки собираются вложением: группа с `Вид = ВидГруппыФормы.Страницы`, внутри неё группы
с `Вид = ВидГруппыФормы.Страница`.

### Таблица и её колонки

```bsl
Таблица = Элементы.Добавить("Расш1_Строки", Тип("ТаблицаФормы"));
Таблица.ПутьКДанным = "Объект.Расш1_Строки";

Колонка = Элементы.Добавить("Расш1_СтрокиСумма", Тип("ПолеФормы"), Таблица);
Колонка.ПутьКДанным = "Объект.Расш1_Строки.Сумма";
```

Колонка — это обычное `ПолеФормы` с родителем-таблицей и путём через табличную часть.
Кнопку в командную панель таблицы добавляют с родителем `Таблица.КоманднаяПанель`.

### Конструктор реквизита

`Новый РеквизитФормы(Имя, ТипЗначения, Путь, Заголовок, СохраняемыеДанные)`

Третий параметр — `Путь`, путь к родительскому реквизиту (нужен для колонки таблицы формы).
У реквизита формы **нет** свойства `ПутьКДанным` — оно есть у элемента формы. Это разные объекты,
и путать их — типичная ошибка.

`ИзменитьРеквизиты(Добавляемые, Удаляемые)` принимает два массива; удаление выполняется раньше
добавления. Вызывается только на сервере.

### Описание типа: в конфигурациях на БСП

Для строки, числа и даты бери готовые функции — они короче и задают квалификаторы:

```bsl
ОбщегоНазначения.ОписаниеТипаСтрока(100)
ОбщегоНазначения.ОписаниеТипаЧисло(15, 2)
ОбщегоНазначения.ОписаниеТипаДата(ЧастиДаты.Дата)
```

Для Булево и ссылочных типов аналога в БСП нет — `Новый ОписаниеТипов("Булево")`,
`Новый ОписаниеТипов("СправочникСсылка.Контрагенты")`.

### Ловушка: обращение к программно добавленному реквизиту

Обращаться к такому реквизиту по имени напрямую нельзя — на момент компиляции модуля его
не существует. Только через индексатор:

```bsl
Значение = ЭтотОбъект["Расш1_ВипЗаказ"];   // правильно
Значение = Расш1_ВипЗаказ;                 // ошибка компиляции
```

Так же обращается к добавленному реквизиту и сам первоисточник. Требованию `std519` обращаться
к реквизитам формы напрямую это не противоречит: там речь о реквизитах, объявленных в форме,
а не о созданных кодом.

### Обработчик события программно созданного элемента

Обработчик назначается методом элемента:

```bsl
Поле.УстановитьДействие("ПриИзменении", "Расш1_ВипЗаказПриИзменении");
```

Сама процедура-обработчик должна существовать в модуле формы **заранее**, на этапе
конфигурирования — программно её не создать. В расширении это значит: процедуру объявляешь
в модуле расширяющей формы, а `УстановитьДействие()` вызываешь из `ПриСозданииНаСервере`
(который сам подключён привязкой к событию, см. начало раздела).

Не путать два разных «назначения обработчика»: `УстановитьДействие()` вешает обработчик
на **программно созданный** элемент, а привязка в свойствах формы перехватывает событие
**типового** элемента или самой формы.

## Паттерн: динамические списки — настройка и оптимизация

**Почему:** Динамический список — основной способ отображения больших данных (справочники, документы, регистры). Он автоматически реализует пагинацию, поиск, сортировку. Неправильная настройка приводит к медленной загрузке и зависанию формы.

### Правильная настройка в ПриСозданииНаСервере

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    
    // Программная настройка динамического списка
    Список = Элементы.СписокДокументов;
    
    // Установка отбора через параметры (НЕ через фиксированные настройки!)
    ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбораДинамическогоСписка(
        СписокДокументов,
        "Организация",
        Организация,
        ВидСравненияКомпоновкиДанных.Равно,
        ,
        ЗначениеЗаполнено(Организация));
    
КонецПроцедуры
```

### Произвольный запрос для динамического списка

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    
    // Произвольный запрос — когда нужно показать данные из нескольких таблиц
    СписокДокументов.ПроизвольныйЗапрос = Истина;
    СписокДокументов.ТекстЗапроса =
    "ВЫБРАТЬ
    |   Реализация.Ссылка,
    |   Реализация.Дата,
    |   Реализация.Номер,
    |   Реализация.Контрагент,
    |   Реализация.СуммаДокумента,
    |   ЕСТЬNULL(Задолженность.СуммаОстаток, 0) КАК ОстатокЗадолженности
    |ИЗ
    |   Документ.РеализацияТоваровУслуг КАК Реализация
    |       ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ВзаиморасчетыСКонтрагентами.Остатки КАК Задолженность
    |       ПО Реализация.Контрагент = Задолженность.Контрагент
    |           И Реализация.Договор = Задолженность.Договор
    |{ГДЕ
    |   Реализация.Дата >= &ДатаНачала}";
    
    СписокДокументов.Параметры.УстановитьЗначениеПараметра("ДатаНачала", НачалоМесяца(ТекущаяДатаСеанса()));
    
КонецПроцедуры
```

### Правила работы с динамическими списками

1. **Не загружайте все данные** — динамический список сам реализует пагинацию
2. **Отборы через КомпоновкаДанных** — не через WHERE в запросе (пользователь сможет изменять отборы)
3. **Индексируйте поля сортировки** — динамический список часто сортирует по дате, номеру
4. **Не используйте УПОРЯДОЧИТЬ ПО** в произвольном запросе — сортировка задаётся настройками списка

## Паттерн: условное оформление — программная настройка

**Почему:** Условное оформление позволяет визуально выделять строки формы (цветом, шрифтом) на основе данных. Программная настройка в `ПриСозданииНаСервере` предпочтительнее настройки в конфигураторе, потому что:
- Можно задать динамические условия (зависящие от параметров)
- Проще поддерживать — код vs визуальный конструктор
- Работает с произвольными запросами

### Пример: подсветка просроченных документов

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    
    УстановитьУсловноеОформление();
    
КонецПроцедуры

&НаСервере
Процедура УстановитьУсловноеОформление()
    
    УсловноеОформление.Элементы.Очистить();
    
    // Правило 1: просроченные документы — красным фоном
    ЭлементУО = УсловноеОформление.Элементы.Добавить();
    
    // Условие: дата оплаты < текущая дата И статус = "Не оплачен"
    ЭлементОтбора = ЭлементУО.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
    ЭлементОтбора.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("ДатаОплаты");
    ЭлементОтбора.ВидСравнения = ВидСравненияКомпоновкиДанных.Меньше;
    ЭлементОтбора.ПравоеЗначение = ТекущаяДатаСеанса();
    ЭлементОтбора.Использование = Истина;
    
    ЭлементОтбора2 = ЭлементУО.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
    ЭлементОтбора2.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("Оплачен");
    ЭлементОтбора2.ВидСравнения = ВидСравненияКомпоновкиДанных.Равно;
    ЭлементОтбора2.ПравоеЗначение = Ложь;
    ЭлементОтбора2.Использование = Истина;
    
    ЭлементУО.Оформление.УстановитьЗначениеПараметра("ЦветТекста", ЦветаСтиля.ПросроченныеДанные);
    
    // Область применения — вся строка таблицы
    ПолеОформления = ЭлементУО.Поля.Элементы.Добавить();
    ПолеОформления.Поле = Новый ПолеКомпоновкиДанных("СписокДокументов");
    
КонецПроцедуры
```

Набор элементов стиля у каждой конфигурации свой: `ПросроченныеДанные` может отсутствовать —
тогда его заводят в конфигурации.

## Паттерн: управление видимостью и доступностью элементов

**Почему:** Скрытие/показ элементов формы программно — стандартный способ адаптации интерфейса под бизнес-логику. Но неправильное управление (слишком много серверных вызовов, изменение видимости из клиентского обработчика без батчинга) приводит к «дёрганию» интерфейса и лишним вызовам сервера.

### Правильно — настройка при создании и по событиям

```bsl
// При создании — начальная настройка
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    
    УправлениеВидимостью();
    
КонецПроцедуры

// Общая процедура управления видимостью — вызывается из разных мест
&НаСервере
Процедура УправлениеВидимостью()
    
    ЭтоУслуга = Объект.ВидОперации = Перечисления.ВидыОпераций.Услуга;
    
    // Группируем изменения — все в одном серверном вызове
    Элементы.Склад.Видимость = НЕ ЭтоУслуга;
    Элементы.ТоварыКоличество.Видимость = НЕ ЭтоУслуга;
    Элементы.ТоварыЕдиницаИзмерения.Видимость = НЕ ЭтоУслуга;
    Элементы.ГруппаДоставка.Видимость = НЕ ЭтоУслуга;
    
    // Доступность
    Элементы.Контрагент.ТолькоПросмотр = Объект.Проведен;
    
КонецПроцедуры

// При изменении вида операции
&НаКлиенте
Процедура ВидОперацииПриИзменении(Элемент)
    // Один серверный вызов для всех изменений видимости
    УправлениеВидимостью();
КонецПроцедуры
```

### Неправильно — изменение видимости по одному элементу

```bsl
// ❌ ПЛОХО: 4 серверных вызова вместо одного
&НаКлиенте
Процедура ВидОперацииПриИзменении(Элемент)
    УстановитьВидимостьСклада();     // вызов 1
    УстановитьВидимостьКоличества(); // вызов 2
    УстановитьВидимостьЕдиницы();    // вызов 3
    УстановитьВидимостьДоставки();   // вызов 4
КонецПроцедуры
```

## Паттерн: работа с табличными частями на форме

**Почему:** Табличные части — основной способ хранения множественных данных (строки документов, контакты контрагентов). Типичные ошибки: пересчёт в цикле с серверными вызовами, некорректная работа с текущей строкой, потеря данных при редактировании.

### Пересчёт строки — на клиенте, если возможно

```bsl
// Изменение количества — пересчёт суммы можно сделать на клиенте
&НаКлиенте
Процедура ТоварыКоличествоПриИзменении(Элемент)
    ТекущаяСтрока = Элементы.Товары.ТекущиеДанные;
    ТекущаяСтрока.Сумма = РассчитатьСумму(
        ТекущаяСтрока.Количество, ТекущаяСтрока.Цена, ТекущаяСтрока.СтавкаНДС);
КонецПроцедуры

// Изменение номенклатуры — нужен сервер для получения данных
&НаКлиенте
Процедура ТоварыНоменклатураПриИзменении(Элемент)
    ТекущаяСтрока = Элементы.Товары.ТекущиеДанные;
    ДанныеНоменклатуры = ПолучитьДанныеНоменклатуры(ТекущаяСтрока.Номенклатура);
    
    // Заполняем всё на клиенте из полученных данных
    ТекущаяСтрока.ЕдиницаИзмерения = ДанныеНоменклатуры.ЕдиницаИзмерения;
    ТекущаяСтрока.Цена = ДанныеНоменклатуры.Цена;
    ТекущаяСтрока.СтавкаНДС = ДанныеНоменклатуры.СтавкаНДС;
    ТекущаяСтрока.Сумма = РассчитатьСумму(
        ТекущаяСтрока.Количество, ТекущаяСтрока.Цена, ТекущаяСтрока.СтавкаНДС);
КонецПроцедуры
```

### Обход табличной части — на клиенте

```bsl
// Пересчёт итога по табличной части — можно на клиенте
&НаКлиенте
Процедура ПересчитатьИтого()
    ИтогоСумма = 0;
    Для Каждого СтрокаТовара Из Объект.Товары Цикл
        ИтогоСумма = ИтогоСумма + СтрокаТовара.Сумма;
    КонецЦикла;
    
    // Обновляем реквизит формы (не объекта!) — для отображения итога
    ИтогоПоДокументу = ИтогоСумма;
КонецПроцедуры
```

## Паттерн: сообщение пользователю с привязкой к полю формы

Сообщение, привязанное к полю, подсвечивает реквизит и работает одинаково в тонком/веб-клиенте:

```bsl
// Сервер (БСП): третий параметр - путь к полю
ОбщегоНазначения.СообщитьПользователю(
    НСтр("ru = 'Контрагент не указан'"), , "Объект.Контрагент");

// Клиент (БСП)
ОбщегоНазначенияКлиент.СообщитьПользователю(
    НСтр("ru = 'Контрагент не указан'"), , "Объект.Контрагент");

// Без БСП - платформенный аналог
Сообщение = Новый СообщениеПользователю;
Сообщение.Текст = НСтр("ru = 'Контрагент не указан'");
Сообщение.Поле = "Объект.Контрагент";
```

## Паттерн: правила новых форм

- Шапка и табличные части — на разных закладках
- «Путь к данным шапки» — заполнять
- Ширина полей ссылочного типа: не более 27 символов
- Многострочные поля комментариев: ширина 79 символов, высота 3 строки
- Включай «Проверку заполнения» на реквизитах формы. При программной записи, где нужна проверка, вызывай ПроверитьЗаполнение() явно (при интерактивной записи платформа выполняет ОбработкуПроверкиЗаполнения сама)
- Для команд, изменяющих данные, включай флаг «Изменяет сохраняемые данные»
- Новые элементы на типовых формах — с префиксом (норма — в `.claude/rules/1c-rules.md`, ### Именование метаданных)
