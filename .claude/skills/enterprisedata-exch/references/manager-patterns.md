## Каркас модуля менеджера

Экспортный интерфейс, который вызывает БСП:

| Метод | Назначение |
|---|---|
| `ПередКонвертацией(КомпонентыОбмена)` | Начало сеанса: заполнение параметров конвертации, кэшей, адаптация правил под версию |
| `ПослеКонвертации(КомпонентыОбмена)` | Конец сеанса: пакетная дообработка, дописывание объектов в сообщение |
| `ПередОтложеннымЗаполнением(КомпонентыОбмена)` | Перед очередью `ПослеЗагрузкиВсехДанных` |
| `ПередОбработкойУдаляемогоОбъекта(КомпонентыОбмена, УдаляемыйОбъект)` | Перед применением полученного удаления |
| `ВерсияФорматаМенеджераОбмена()` | Контракт менеджер↔БСП (`"1"`, `"2"`, `"3"`), не версия EnterpriseData |
| `ЗаполнитьПравилаОбработкиДанных(Направление, ПравилаОбработкиДанных)` | ПОД |
| `ЗаполнитьПравилаКонвертацииОбъектов(Направление, ПравилаКонвертации)` | ПКО и ПКС |
| `ЗаполнитьПравилаКонвертацииПредопределенныхДанных(Направление, ПравилаКонвертации)` | ПКПД |
| `ЗаполнитьПараметрыКонвертации(ПараметрыКонвертации)` | Объявление ключей параметров |
| `ВыполнитьПроцедуруМодуляМенеджера(ИмяПроцедуры, Параметры)` | Диспетчер всех обработчиков правил |

**Диспетчер — ключевой участок.** Правила хранят имена обработчиков строками, а БСП вызывает их только через `ВыполнитьПроцедуруМодуляМенеджера` — длинную цепочку `Если ИмяПроцедуры = "..." Тогда`. Обработчик, для имени которого в диспетчере нет ветки, не вызовется, и ошибки об этом не будет. Для `ВыборкаДанных` ПОД БСП вызывает отдельный `ВыполнитьФункциюМодуляМенеджера` — проверь, есть ли он в твоем менеджере (в УТ 11.5.27 его нет).

Внутренние помощники сгенерированного менеджера, которые встречаются почти везде: `ДобавитьПКС`, `ДобавитьПКТЧ`, `ВерсияФорматаЧислом`, `СвойствоФорматаОбмена`, `ЗначениеВИнструкциюПКО`, `ОчиститьИспользованиеПКО`, `ЗаполнитьСвойстваШапкиОбъекта`, `ЗаполнитьРеквизиты`. Они не экспортные.

## Порядок вызовов в сеансе

**Отправка** (`ПроизвестиВыгрузкуДанных`):

1. `ПередКонвертацией`.
2. Выборка изменений узла; на каждый объект — ПОД `ПриОбработке`, затем по каждому разрешенному ПКО `ПриОтправкеДанных` и запись XDTO в файл.
3. `ПослеКонвертации` — **до закрытия элемента `Body`**: отсюда еще можно дописать объекты в сообщение через `ОбменДаннымиXDTOСервер.ВыгрузкаОбъектаВыборки`.
4. Квитирование, номер отправленного, закрытие `Body` и `Message`.

Если на шаге 2 взведен `ФлагОшибки`, исключение вызывается до `ПослеКонвертации`.

**Получение** (`ПроизвестиЧтениеДанных`):

1. `ПередКонвертацией`.
2. Чтение сообщения: на каждый объект — ПОД `ПриОбработке`, затем ПКО (`ПриКонвертацииДанныхXDTO` → поиск → `ПередЗаписьюПолученныхДанных` → запись). Здесь же копится список удалений: и полученные удаления, и объекты по снятым ПКО (см. «Рычаги управления»).

Шаги 3–6 выполняются, **только если после чтения нет `ФлагОшибки` и включен `РежимЗагрузкиДанныхВИнформационнуюБазу`**:

3. Применение удалений (с `ПередОбработкойУдаляемогоОбъекта`), удаление временных объектов, созданных по ссылкам.
4. `ПередОтложеннымЗаполнением`, затем очередь `ПослеЗагрузкиВсехДанных`.
5. `ПослеКонвертации` — при повторной проверке `ФлагОшибки` (его могли взвести шаги 3–4).
6. Отложенное проведение документов, отложенная запись объектов.

Следствия: ошибка в любом объекте сообщения отменяет для всего сеанса и удаления, и отложенное заполнение, и `ПослеКонвертации`, и проведение; в `ПослеКонвертации` загруженные документы еще не проведены — не клади туда то, что обязано отработать всегда.

## Сигнатуры обработчиков и что из них возвращается

БСП передает параметры структурой `Параметры` и после вызова забирает обратно только часть полей. Присвоение остальным до БСП не доходит.

Контракт — **имена полей структуры**, а не имена и порядок параметров процедуры-обработчика: диспетчер раскладывает поля в аргументы как угодно. В типовом менеджере ПОД получает `Параметры.ОбъектОбработки` в параметр с именем `ДанныеИБ` или `ДанныеXDTO`, а порядок аргументов у обработчиков `ПослеЗагрузкиВсехДанных` разный.

| Обработчик | Поля `Параметры` | Что БСП забирает обратно |
|---|---|---|
| ПОД отправки `ПриОбработке` | `ОбъектОбработки` (объект базы), `ИспользованиеПКО`, `КомпонентыОбмена` | `ИспользованиеПКО`, `ОбъектОбработки`; изменения свойств объекта видны дальше (тот же объект) |
| ПОД получения `ПриОбработке` | `ОбъектОбработки` (структура `ДанныеXDTO`), `ИспользованиеПКО`, `КомпонентыОбмена` | `ИспользованиеПКО`, `ОбъектОбработки`; правки содержимого структуры |
| ПКО `ПриОтправкеДанных` | `ДанныеИБ`, `ДанныеXDTO`, `КомпонентыОбмена`, `СтекВыгрузки` | `ДанныеXDTO` (в т.ч. `Неопределено`); `ДанныеИБ` — нет |
| ПКО `ПриКонвертацииДанныхXDTO` | `ДанныеXDTO`, `ПолученныеДанные`, `КомпонентыОбмена` | `ДанныеXDTO`, `ПолученныеДанные` |
| ПКО `ПередЗаписьюПолученныхДанных` | `ДанныеИБ`, `ПолученныеДанные`, `КонвертацияСвойств`, `КомпонентыОбмена` | `ПолученныеДанные`, `ДанныеИБ` (в т.ч. `Неопределено`) |
| ПКО `ПослеЗагрузкиВсехДанных` | `Объект`, `КомпонентыОбмена`, `ОбъектМодифицирован` (приходит `Истина`) | `ОбъектМодифицирован` |
| ПКО `АлгоритмПоиска` | `ДанныеИБ`, `ПолученныеДанные`, `КомпонентыОбмена` | `ДанныеИБ` — найденная ссылка |

Обработчик `ПослеЗагрузкиВсехДанных`, которому диспетчер не передает `ОбъектМодифицирован` (в типовом менеджере такие есть), сбросить флаг не может — объект всегда записывается второй раз.

`ИспользованиеПКО` — структура «имя ПКО → Булево», заранее заполненная `Истина` по всем ПКО из `ИспользуемыеПКО` ПОД.

## Рычаги управления из обработчика

| Нужно | Как делают в типовом менеджере |
|---|---|
| Не выгружать объект | ПОД: `ОчиститьИспользованиеПКО(ИспользованиеПКО)`; ПКО: `ДанныеXDTO = Неопределено` |
| Выбрать ПКО по данным | ПОД: сначала все в `Ложь`, затем нужное в `Истина` |
| Подставить ПКО, которого нет в ПОД | ПОД: `ИспользованиеПКО.Вставить("ИмяПКО", Истина)` |
| Не загружать объект | `ПередЗаписьюПолученныхДанных`: обнулить и `ПолученныеДанные`, и `ДанныеИБ` — запись не выполняется, существующий объект не трогается. **Не** снимать ПКО в ПОД получения — см. ниже |
| Самому слить полученное с существующим | `ПередЗаписьюПолученныхДанных`: перенести нужное в `ДанныеИБ`, затем `ПолученныеДанные = Неопределено` — БСП не вызывает автоматическое заполнение и пишет `ДанныеИБ` как есть |
| Отменить применение удаления | `ПередОбработкойУдаляемогоОбъекта`: `УдаляемыйОбъект = Неопределено` |
| Удалить движения при удалении через отмену проведения | `ПередОбработкойУдаляемогоОбъекта`: `ДополнительныеСвойства.Вставить("ИспользоватьОтменуПроведенияДляОчисткиДвижений", Истина)` |
| Передать данные между этапами одного объекта при получении | `ПолученныеДанные.ДополнительныеСвойства`: оттуда читает второй этап ПКС, `ПередЗаписью...`; БСП переносит их и в `ПослеЗагрузкиВсехДанных` |
| Передать вычисленное из ПОД в ПКО при отправке | `ДанныеИБ.ДополнительныеСвойства.Вставить("ДанныеШапки", ...)` в ПОД, чтение в `ПриОтправкеДанных` |
| Поменять правило на лету | В обработчике или `ПередКонвертацией` найти строку в `КомпонентыОбмена.ПравилаКонвертацииОбъектов` / `ПравилаКонвертацииПредопределенныхДанных` и изменить `ПоляПоиска`, `ПравилоКонвертацииСвойства` ПКС, `КонвертацииЗначенийПриОтправке/ПриПолучении` |

**`ОчисткаДанных` у ПОД.** Если у ПОД несколько ПКО и часть из них снята, БСП выгружает **удаление** объекта по снятым ПКО — на случай, если раньше он ушел по ним. Подавляет это колонка `ОчисткаДанных = Ложь`. Колонки в библиотечной таблице ПОД нет: менеджер УТ добавляет ее сам в начале `ЗаполнитьПравилаОбработкиДанных` и заполняет у каждого ПОД отправки. Добавляя свой ПОД с несколькими ПКО, заполни ее явно.

**Снятое ПКО у ПОД получения — это удаление.** Если ПКО снято (`Ложь` в `ИспользованиеПКО`), идентифицирует объект по уникальному идентификатору, а в объекте XDTO есть ссылка, БСП кладет объект с этим идентификатором в список на удаление — одинаково при одном ПКО и при нескольких, колонка `ОчисткаДанных` здесь не участвует. Существующий у получателя объект будет помечен на удаление (проведенный документ — с отменой проведения), если тот же объект не загружен в этом сеансе другим ПКО. Поэтому «не загружать» и «удалить» — разные рычаги: снимать ПКО на получении можно, только когда удаление и есть цель или когда объект гарантированно загружается другим ПКО.

## Ошибки в обработчиках

| Где | Что происходит |
|---|---|
| ПОД `ПриОбработке`, отправка | Перехватывается по объекту, проблема регистрируется, объект пропускается **и взводится `ФлагОшибки`** — сообщение целиком не формируется |
| ПОД `ПриОбработке`, получение | Перехватывается по объекту, проблема регистрируется, объект пропускается, чтение остальных продолжается; в конце взводится `ФлагОшибки` — шаги 3–6 получения не выполняются |
| ПКО на отправке | Перехватывается по объекту, регистрируется проблема и взводится `ФлагОшибки` — сообщение целиком не формируется |
| ПКО на получении (все обработчики конвертации и записи объекта) | Перехватывается по объекту — так же, как ПОД получения: проблема регистрируется, остальные объекты читаются, затем `ФлагОшибки` |
| `ПередКонвертацией`, `ПослеКонвертации`, `ПередОтложеннымЗаполнением` | Исключение прерывает сеанс |
| Очередь `ПослеЗагрузкиВсехДанных` | Своя транзакция на объект, но исключение пробрасывается и прерывает этап |
| `ПередОбработкойУдаляемогоОбъекта` | **Поглощается пустым `Исключение`** — ошибка не видна нигде |

Для мягкого предупреждения без остановки обмена в УТ есть свой помощник: пишет в журнал регистрации и ставит в параметрах флаг `ПриСинхронизацииЗарегистрированоПредупреждение`, а `ПослеКонвертации` переводит результат в `ВыполненоСПредупреждениями`. Другой путь — `ОбменДаннымиXDTOСервер.ЗаписатьВПротоколВыполнения(КомпонентыОбмена, Текст, Неопределено, Ложь)` (последний параметр — не взводить флаг ошибки) плюс установка `СостояниеОбменаДанными.РезультатВыполненияОбмена`.

## Параметры конвертации: объявление, заполнение, виды

**Объявление.** `ЗаполнитьПараметрыКонвертации` только вставляет ключи без значений. БСП вызывает ее при инициализации компонентов и кладет результат в `КомпонентыОбмена.ПараметрыКонвертации` (структура). Присваивание `ПараметрыКонвертации.Ключ = ...` по необъявленному ключу упадет — либо объяви ключ, либо используй `Вставить`.

**Заполнение — в `ПередКонвертацией`, раздельно по направлению** (`КомпонентыОбмена.НаправлениеОбмена`). Источники:

- константы и функциональные опции (`ПолучитьФункциональнуюОпцию`);
- реквизиты узла — одним `ОбщегоНазначения.ЗначенияРеквизитовОбъекта(КомпонентыОбмена.УзелКорреспондента, "А, Б, В")` и `ЗаполнитьЗначенияСвойств`; табличные части — через `КомпонентыОбмена.УзелКорреспондентаОбъект` (уже прочитанный объект узла);
- умолчания для обмена без плана обмена: при `КомпонентыОбмена.ЭтоОбменЧерезПланОбмена = Ложь` (выгрузка/загрузка ED обработкой) узла нет, и параметры, которые обычно берутся из узла, заполняются явными значениями.

**Виды параметров** — у каждого свой жизненный цикл:

| Вид | Пример в УТ | Когда создается / используется |
|---|---|---|
| Настройка | `ВыгружатьАналитикуПоСкладам`, `ВидыЦенНоменклатуры` (список из ТЧ узла) | `ПередКонвертацией` → читается в ПОД/ПКО |
| Кэш справочных данных | `КодыВидовНоменклатурнойКлассификации` | `ПередКонвертацией` → поиск в ПКО |
| Ленивый кэш | `ЗначенияФО`, `ЭлементыПоУмолчанию` | Пустое соответствие/структура, наполняется при первом обращении |
| Накопитель для пакетной обработки | `НоменклатураДляОтложеннойОбработки`, `ЗаполнитьОбъектРасчетов`, `КассовыеСменыКЗакрытию` | Пустая коллекция в `ПередКонвертацией` → наполняется в обработчиках → обрабатывается в `ПослеКонвертации` |
| Флаг состояния | `ПриСинхронизацииЗарегистрированоПредупреждение` | Сбрасывается в `ПередКонвертацией`, читается в `ПослеКонвертации` |
| Довыгрузка | `СозданныеПриВыгрузкеОбъекты` | Объекты, созданные во время выгрузки, дописываются в сообщение в `ПослеКонвертации` |

Накопитель-таблицу создают с типизированными колонками, если по ним потом пойдет запрос (`Новый ОписаниеТипов("ДокументСсылка.Х")`), — тогда ее можно передать параметром запроса.

## Кэширование

Все кэши живут в `ПараметрыКонвертации` — значит, ровно один сеанс обмена. Между сеансами ничего не сохраняется.

**Справочник из общего макета, разобранный один раз.** В `ПередКонвертацией` на получении:

```bsl
Данные = ПолучитьОбщийМакет("КодВидаНоменклатурнойКлассификации").ПолучитьТекст();
ТЗКодов = Новый ТаблицаЗначений;
ТЗКодов.Колонки.Добавить("Код");
ТЗКодов.Колонки.Добавить("Наименование");
ТЗКодов.Индексы.Добавить("Код"); // поиск Найти по индексированной колонке
// ... ЧтениеXML: на каждый элемент ВидНоменклатурнойКлассификации — строка (атрибуты КодВида, Имя)
ПараметрыКонвертации.Вставить("КодыВидовНоменклатурнойКлассификации", ТЗКодов);
```

Потребитель — `ПриКонвертацииДанныхXDTO` номенклатуры: `ТЗКодов.Найти(ДанныеXDTO.КодВидаНоменклатурнойКлассификации, "Код")`, найденное наименование кладется в `ПолученныеДанные.ДополнительныеСвойства`. Так на каждый объект — поиск по индексу в памяти вместо чтения макета или запроса.

**Ленивый кэш значения:**

```bsl
Функция ЗначениеФО(ИмяФО, КомпонентыОбмена)
	ЗначенияФО = КомпонентыОбмена.ПараметрыКонвертации.ЗначенияФО; // Соответствие, создано в ПередКонвертацией
	ЗначениеФО = ЗначенияФО.Получить(ИмяФО);
	Если ЗначениеФО = Неопределено Тогда
		ЗначениеФО = ПолучитьФункциональнуюОпцию(ИмяФО);
		ЗначенияФО.Вставить(ИмяФО, ЗначениеФО);
	КонецЕсли;
	Возврат ЗначениеФО;
КонецФункции
```

**Ленивый кэш с созданием** (`ЭлементПоУмолчанию(КомпонентыОбмена, ВидЭлемента)`): структура в параметрах; при промахе — запрос, при отсутствии элемента — создание, результат запоминается. Так на весь сеанс создается не больше одного «элемента по умолчанию» каждого вида.

## Что делают в ПослеКонвертации

**Получение** (только при `РежимЗагрузкиДанныхВИнформационнуюБазу`):

- прикладной пост-обработчик загрузки конфигурации (в УТ `ОбменДаннымиУТ.ПослеЗагрузкиДанных`: включает функциональные опции по факту загруженных данных);
- пакетная дообработка накопителей: один запрос по массиву ссылок → `ПолучитьОбъект()` → правка → `ОбменДанными.Загрузка = Истина` → `Записать()` в `Попытка` с записью ошибки в журнал по объекту;
- создание производных документов по накопленной таблице (в УТ — счета-фактуры по загруженным авансовым отчетам);
- перевод результата в `ВыполненоСПредупреждениями`, если был взведен флаг предупреждения.

**Отправка** (вызывается, только если при выгрузке не взведен `ФлагОшибки`):

- дописывание объектов, созданных во время выгрузки: `ОбменДаннымиСервер.ВыбратьИзменения(Узел, НомерОтправленного, Массив)` → `ОбменДаннымиXDTOСервер.ВыгрузкаОбъектаВыборки(КомпонентыОбмена, Данные)`;
- тот же перевод результата по флагу предупреждения.

**Почему накопитель, а не правка в `ПослеЗагрузкиВсехДанных`.** Отложенный обработчик вызывается на каждый объект в своей транзакции. Если для дозаполнения нужны данные многих объектов или один запрос на всех, обработчик только добавляет ссылку в накопитель, а работа выполняется в `ПослеКонвертации` разом.

## Приемы отправки

**Выход в режиме «только ссылка».** Когда объект выгружается как ссылка из другого объекта, `СтекВыгрузки.Количество() > 1`. БСП в этом режиме выполняет только ПКС с `ОбработкаКлючевогоСвойства`, а то, что обработчик положил в `ДанныеXDTO.КлючевыеСвойства`, переносит в корень. Тяжелые вычисления в начале обработчика отсекают так:

```bsl
Если СтекВыгрузки.Количество() > 1 Тогда
	Возврат;
КонецЕсли;
```

Если ключевые свойства вычисляемые, заполни их до этой проверки.

**Ключевые и обычные свойства.** Ключевое — `ДанныеXDTO.КлючевыеСвойства.Вставить(...)`, обычное — `ДанныеXDTO.Вставить(...)`.

**Инструкция вместо значения.** `ДанныеXDTO.Вставить("Свойство", Новый Структура("Значение, ИмяПКО", Ссылка, "ИмяПКО"))` — для полиморфных свойств и когда ПКО свойства зависит от версии формата. Помощник `ЗначениеВИнструкциюПКО` подбирает ПКО по типу значения и возвращает `Неопределено`, если подходящих ПКО больше одного.

**`AdditionalInfo` дополняют, а не заменяют:**

```bsl
Если ДанныеXDTO.Свойство("AdditionalInfo") И ТипЗнч(ДанныеXDTO.AdditionalInfo) = Тип("Структура") Тогда
	ДополнительныеДанные = ДанныеXDTO.AdditionalInfo;
Иначе
	ДополнительныеДанные = Новый Структура;
КонецЕсли;
ДополнительныеДанные.Вставить("Ключ", Значение);
ДанныеXDTO.Вставить("AdditionalInfo", ДополнительныеДанные);
```

Ссылку через `AdditionalInfo` передают строкой УИД; приемник восстанавливает ее через `СсылкаОбъектаПоУИДОбъектаXDTO` (см. ниже).

**Один объект базы → несколько объектов формата.** ПОД собирает структуру с данными (`Ссылка`, реквизиты, таблицы) и вызывает `ОбменДаннымиXDTOСервер.ВыгрузкаОбъектаВыборки(КомпонентыОбмена, Структура, ПравилоОбработки)`, а исходному объекту снимает ПКО. ПКО для структуры объявляется с `ОбъектДанных = Неопределено` (в УТ — суффикс `_ИзСтруктуры`). Тот же ПОД вызывается повторно уже для структуры, поэтому он начинается с защиты: `Если ТипЗнч(ДанныеИБ) = Тип("Структура") Тогда Возврат; КонецЕсли;`. Правило ищут через `КомпонентыОбмена.ПравилаОбработкиДанных.Найти("ИмяПОД", "Имя")` и проверяют на `Неопределено`.

**Вычисленное в ПОД — в ПКО.** ПОД отправки получает тот же объект, что потом уходит в ПКО, поэтому результат запроса, нужный для выбора ПКО, кладут в `ДанныеИБ.ДополнительныеСвойства`, и обработчик ПКО его не пересчитывает.

## Приемы получения

**Идиома записи.** Во всех `ПередЗаписьюПолученныхДанных`:

```bsl
ДанныеДляЗаписиВИБ = ?(ДанныеИБ = Неопределено, ПолученныеДанные, ДанныеИБ);
```

Дальше умолчания ставятся в `ДанныеДляЗаписиВИБ` — они попадают в запись и для нового, и для найденного объекта. `ДанныеИБ.Ссылка` при новом объекте недоступна: ссылка нового — `ПолученныеДанные.ПолучитьСсылкуНового()`.

**Сохранить локальные значения шапки**, которых нет в сообщении: до автоматического переноса скопировать их из `ДанныеИБ` в `ПолученныеДанные`, если там пусто. В УТ — помощник `ЗаполнитьРеквизиты(ПолученныеДанные, ДанныеИБ, "СтавкаНДС, ГруппаАналитическогоУчета")`.

**Сохранить локальные колонки строк ТЧ.** Автоматический перенос заменяет ТЧ найденного объекта целиком (см. `architecture.md`). Типовой обход — ручное слияние:

```bsl
Если ДанныеИБ <> Неопределено Тогда
	ЗаполнитьСвойстваШапкиОбъекта(КонвертацияСвойств, ПолученныеДанные, ДанныеИБ); // шапка по ПКС
	// В новые строки переносятся значения старых строк с теми же ключами,
	// кроме перечисленных колонок: их значения берутся из сообщения.
	ОбменДаннымиXDTOСервер.ЗаполнитьТабличнуюЧастьОбъектаНачальнымиДанными(
		ПолученныеДанные.Товары, ДанныеИБ.Товары,
		"Номенклатура,Характеристика,Упаковка,Серия", Неопределено,
		"Количество, КоличествоУпаковок, Цена, Сумма");
	ДанныеИБ.Товары.Загрузить(ПолученныеДанные.Товары.Выгрузить());
	ПолученныеДанные = Неопределено; // БСП пишет ДанныеИБ как есть
КонецЕсли;
```

Параметры `ЗаполнитьТабличнуюЧастьОбъектаНачальнымиДанными`: (ТЧ после — из сообщения, ТЧ до — из базы, ключевые поля, колонки для включения, колонки для исключения). Для каждой новой строки с найденной по ключу старой выполняется `ЗаполнитьЗначенияСвойств(Новая, Старая, Включить, Исключить)`: исключенные колонки остаются из сообщения, остальные возвращаются из базы. Пара строк сопоставляется, только если ключ встречается **ровно один раз** и в новой, и в старой таблице: строки с повторяющимся ключом молча остаются со значениями из сообщения. Без ключевых полей функция ничего не делает.

`ПолученныеДанные = Неопределено` отключает автоматический перенос **для всего объекта**: все табличные части ПКО и реквизиты, которые не перенес `ЗаполнитьСвойстваШапкиОбъекта` (он берет только шапочные ПКС с заполненным `СвойствоКонфигурации`), обработчик переносит сам.

**Поиск или создание ссылки вложенного объекта по его XDTO:**

```bsl
СтрокаПКО = Новый Структура;
СтрокаПКО.Вставить("ПравилоКонвертации", ОбменДаннымиXDTOСервер.ПКОПоИмени(КомпонентыОбмена, "ИмяПКО"));
СтрокаПКО.Вставить("УдалятьСозданныеПоКлючевымСвойствам", Истина);
Ссылка = ОбменДаннымиXDTOСервер.СтруктураОбъектаXDTOВДанныеИБ(КомпонентыОбмена, ДанныеXDTO.Свойство, СтрокаПКО, "ПолучитьСсылку");
```

Третьим параметром можно передать и само ПКО (`ПКОПоИмени`). Результат — ссылка или объект в зависимости от ветки идентификации; в типовом коде к нему обращаются `.Ссылка`, что работает в обоих случаях.

**`СсылкаОбъектаПоУИДОбъектаXDTO(УИДСтрокой, Тип, КомпонентыОбмена)`** сначала ищет публичный идентификатор, затем ссылку с тем же УИД. Если этот УИД уже сопоставлен другому объекту, она возвращает **новую случайную ссылку**, которой нет в базе. Поэтому после вызова существование проверяют: `Если Ссылка.ПолучитьОбъект() <> Неопределено`.

**ПОД получения как маршрутизатор.** Видит всю структуру XDTO до конвертации: выбирает ПКО по содержимому (`ТипЗначения`, наличие строк, даты), может отказаться от загрузки, дописать в `ДанныеXDTO` вычисленные колонки и заранее найти существующий объект через `СтруктураОбъектаXDTOВДанныеИБ(..., "ПолучитьСсылку")`.

**Регистр сведений.** Для ПКО регистра `ПолученныеДанные` — набор записей, идентификация не выполняется. Обработчик сам ставит `Отбор.<Измерение>.Значение/Использование` и добавляет запись; значения измерений, пришедшие ссылками XDTO, разрешает через `СтруктураОбъектаXDTOВДанныеИБ(..., "ПолучитьСсылку")`.

**Варианты идентификации ПКО:** `ПоУникальномуИдентификатору`, `ПоПолямПоиска`, `СначалаПоУникальномуИдентификаторуПотомПоПолямПоиска`. `ПоляПоиска` — массив строк, каждая строка — набор полей через запятую; наборы перебираются по очереди. Объект, найденный по полям поиска, записывается всегда, даже в режиме `ПолучитьСсылку`. Поля поиска можно переопределить на лету по данным объекта (в УТ так различают физлиц и юрлиц контрагентов).

**Что БСП делает при записи сама:** снимает `ПометкаУдаления`; у проводимого документа с `Проведен = Истина` записывает его непроведенным и ставит в очередь отложенного проведения; у ранее проведенного — отменяет проведение. ПКО, не перечисленное ни в одном ПОД получения своего объекта формата, получает `РазрешитьСоздаватьОбъектИзСтруктуры = Истина`.

## Один менеджер на много версий формата

- В правилах объявляются ПКО всех версий сразу. ПКО, чей объект формата отсутствует в XDTO-схеме текущей версии, БСП молча удаляет из таблицы правил; ПКО, указанное в ПОД, но не найденное, при выгрузке пропускается.
- В обработчиках ветвятся по версии: `ВерсияФорматаЧислом(КомпонентыОбмена.ВерсияФорматаОбмена) >= ВерсияФорматаЧислом("1.17")`. `ВерсияФорматаЧислом` — помощник менеджера («1.17» → 11700); в УТ есть экспортная копия `ОбменДаннымиУТ.ВерсияФорматаЧислом`.
- Наличие объекта или свойства в текущей схеме проверяют по фабрике, а не по номеру версии: помощник `СвойствоФорматаОбмена(КомпонентыОбмена, "Справочник.ГруппыАналитическогоУчетаНоменклатуры")` смотрит `ФабрикаXDTO.Тип(Новый ТипДанныхXML(Имя, КомпонентыОбмена.XMLСхема))` и спускается по точкам к свойствам.
- Значения перечислений, появившиеся в новых версиях, дописывают в `КонвертацииЗначенийПриОтправке/ПриПолучении` нужной ПКПД в `ПередКонвертацией` по версии (в УТ — процедура адаптации ПКПД).

## Подключение к менеджеру из расширения

Рекомендуемые точки для расширения общего модуля менеджера (прочие нормы оформления — скилл `config-modification`):

| Задача | Точка |
|---|---|
| Свой параметр конвертации | `&После("ЗаполнитьПараметрыКонвертации")`: `ПараметрыКонвертации.Вставить("префикс_Ключ")` |
| Заполнить параметр, кэш, накопитель | `&После("ПередКонвертацией")` с проверкой направления |
| Пакетная дообработка | `&После("ПослеКонвертации")`; помни, что при ошибке загрузки она не вызывается |
| Свой обработчик правила | Имя обработчика в правиле + `&Вместо("ВыполнитьПроцедуруМодуляМенеджера")`: свое имя — вызвать свою процедуру, иначе `ПродолжитьВызов(ИмяПроцедуры, Параметры)` |
| Добавить или поправить ПКО/ПКС | `&После("ЗаполнитьПравилаКонвертацииОбъектов")`: найти строку по `ИмяПКО`, проверить направление, поменять имя обработчика или добавить ПКС |
| Дополнить типовой обработчик | `&После` на саму процедуру обработчика: параметры те же, что в таблице сигнатур |

Ветка диспетчера передает поля структуры `Параметры` аргументами, как типовые ветки. Присваивание параметру внутри процедуры (например, `ПолученныеДанные = Неопределено`) попадает обратно в поле структуры, и БСП его читает:

```bsl
&Вместо("ВыполнитьПроцедуруМодуляМенеджера")
Процедура префикс_ВыполнитьПроцедуруМодуляМенеджера(ИмяПроцедуры, Параметры)
	Если ИмяПроцедуры = "префикс_ПКО_Х_Получение_ПередЗаписьюПолученныхДанных" Тогда
		префикс_ПКО_Х_Получение_ПередЗаписьюПолученныхДанных(
			Параметры.ПолученныеДанные, Параметры.ДанныеИБ, Параметры.КонвертацияСвойств, Параметры.КомпонентыОбмена);
	Иначе
		ПродолжитьВызов(ИмяПроцедуры, Параметры);
	КонецЕсли;
КонецПроцедуры
```

Состав полей `Параметры` по видам обработчиков — в таблице «Сигнатуры обработчиков», колонка «Поля `Параметры`». У ПОД объект лежит в `Параметры.ОбъектОбработки`, а не в `ДанныеИБ`/`ДанныеXDTO`: обращение по имени параметра из типового обработчика упадет на первом вызове.

Если у ПКО **уже есть** типовой обработчик нужного события, проще повесить `&После` на эту процедуру, чем менять имя в правиле: диспетчер трогать не нужно. Если обработчика нет — только имя в правиле плюс ветка диспетчера. Неэкспортные помощники менеджера (`ДобавитьПКС`, `ВерсияФорматаЧислом`) в модуле расширения того же общего модуля доступны по правилам платформы для расширений модулей — проверь на своей версии платформы до того, как опираться.

## Частые ошибки

| Ошибка | Правильно |
|---|---|
| Новый обработчик прописан в правиле, но не вызывается | Добавить ветку в диспетчер (`&Вместо` на `ВыполнитьПроцедуруМодуляМенеджера`) или перехватить существующий обработчик |
| `ПараметрыКонвертации.МойКлюч = ...` падает | Объявить ключ в `ЗаполнитьПараметрыКонвертации` или использовать `Вставить` |
| Кэш собирается в обработчике ПКО на каждый объект | Собрать в `ПередКонвертацией` в `ПараметрыКонвертации`, в ПКО — поиск по индексу |
| Пакетная дообработка в `ПослеКонвертации` обязана выполниться всегда | Она не вызывается при `ФлагОшибки`; документы к этому моменту еще не проведены |
| Тяжелый `ПриОтправкеДанных` выполняется для каждой ссылки | `Если СтекВыгрузки.Количество() > 1 Тогда Возврат` после заполнения ключевых свойств |
| Снятое ПКО у ПОД с несколькими ПКО порождает удаление у корреспондента | Задать `ОчисткаДанных = Ложь` у ПОД |
| Обращение к `ДанныеИБ.Ссылка` в `ПередЗаписью...` | Для нового объекта `ДанныеИБ = Неопределено`; ссылка — `ПолученныеДанные.ПолучитьСсылкуНового()` |
| Результат `СсылкаОбъектаПоУИДОбъектаXDTO` сразу записан в реквизит | Проверить существование: функция может вернуть новую несуществующую ссылку |
| «Не загружать объект» сделано снятием ПКО в ПОД получения — у получателя объект помечается на удаление | Отказаться от записи в `ПередЗаписьюПолученныхДанных`: обнулить `ПолученныеДанные` и `ДанныеИБ` |
| Ошибка в одном объекте считается локальной — «остальные загрузились» | Любая ошибка ПОД или ПКО взводит `ФлагОшибки`: на отправке не формируется сообщение, на получении не выполняются удаления, отложенное заполнение, `ПослеКонвертации` и проведение |
| Ветка `&Вместо` для обработчика ПОД читает `Параметры.ДанныеИБ` | Объект ПОД — в `Параметры.ОбъектОбработки` |
| Ошибка в `ПередОбработкойУдаляемогоОбъекта` «не воспроизводится» | БСП поглощает исключения этого обработчика; ищи по последствиям, а не по журналу |
| Ветвление по номеру версии там, где важно наличие свойства | Проверять схему через фабрику XDTO (`СвойствоФорматаОбмена`) |
