# Контракт промпта для Codex

Codex — исполнитель, а не собеседник. Промпт ему пишется как техническое задание: что сделать,
в какой форме ответить, что делать по умолчанию, чем проверить себя. Расплывчатый промпт даёт
расплывчатый ответ независимо от модели.

## Четыре правила

1. **Одна задача — один запуск.** «Проверь, почини, обнови документацию и предложи план» —
   это четыре запуска. Смешанные задачи дают частичное выполнение каждой.
2. **Скажи, как выглядит «готово».** Codex не выводит желаемый конец сам: форма ответа, что
   должно быть изменено, что нельзя трогать.
3. **Не проси «думать сильнее» — ужесточи контракт.** Просьба «будь внимательнее» ничего
   не меняет; блок проверки перед финалом и правило заземления — меняют. Уровень рассуждений
   поднимай в последнюю очередь.
4. **Стабильные теги.** Блоки оборачиваются в XML-теги с постоянными именами — так промпт имеет
   структуру, а не абзац пожеланий. Имена тегов английские, содержимое — по-русски.

## Блоки

Обязательный — `<task>`. Остальные добавляются по типу задачи.

| Блок | Когда | Содержание |
|---|---|---|
| `<task>` | всегда | конкретная работа, контекст (файлы, ошибка, механизм), ожидаемый конец |
| `<structured_output_contract>` | нужна форма ответа | точная форма и порядок; самое важное — первым; кратко |
| `<compact_output_contract>` | нужна проза, но короткая | без пересказа и вступлений |
| `<default_follow_through_policy>` | Codex не должен переспрашивать по мелочам | «бери самое разумное низкорисковое толкование и продолжай; спрашивай только там, где деталь меняет корректность, безопасность или необратимое действие» |
| `<completeness_contract>` | отладка, реализация, многошаговые задачи | «доведи до конца; не останавливайся на первом правдоподобном ответе; проверь, нет ли следующих исправлений и краевых случаев» |
| `<verification_loop>` | важна корректность | «перед финалом сверь результат с задачей и с изменёнными файлами; проверка не прошла — исправь, а не докладывай черновик» |
| `<missing_context_gating>` | Codex может начать угадывать | «не угадывай факты о репозитории; нет контекста — добудь инструментами или назови, что осталось неизвестным» |
| `<grounding_rules>` | ревью, исследование, поиск причины | «каждое утверждение — по контексту или выводу инструментов; предположение помечай как предположение» |
| `<action_safety>` | задача с правом записи | «менять только в объёме задачи; никаких попутных рефакторингов и переименований; рискованное или необратимое действие называть до выполнения» |
| `<dig_deeper_nudge>` | ревью | «после первой находки проверь отказы второго порядка: пустые данные, повторы, устаревшее состояние, откат» |
| `<research_mode>` | сравнение вариантов, рекомендация | «раздели наблюдаемые факты, выводы и открытые вопросы; сначала вширь, потом вглубь там, где это меняет рекомендацию» |

## Какие блоки к какой задаче

- **Диагностика, поиск причины:** `task`, `compact_output_contract` (причина → доказательства →
  наименьший безопасный следующий шаг), `default_follow_through_policy`, `verification_loop`,
  `missing_context_gating`.
- **Узкая правка (`-s workspace-write`):** `task`, `structured_output_contract` (что сделано →
  затронутые файлы → чем проверено → остаточные риски), `completeness_contract`,
  `verification_loop`, `action_safety`.
- **Ревью:** `task`, `structured_output_contract` (находки по серьёзности → доказательства →
  следующие шаги), `grounding_rules`, `dig_deeper_nudge`. Адверсарный вариант со схемой —
  `adversarial-review.md`.
- **Второе мнение по решению, сравнение вариантов:** `task`, `structured_output_contract`
  (факты → рекомендация → компромиссы → открытые вопросы), `research_mode`, `grounding_rules`.
- **Продолжение той же сессии (`resume`):** только дельта указания. Полный промпт заново —
  лишь если направление сменилось.

## Анти-паттерны

| Так не надо | Почему | Так надо |
|---|---|---|
| «Посмотри и скажи, что думаешь» | нет задачи и нет формы ответа | `<task>` с конкретным вопросом + контракт вывода |
| «Разберись и доложи» | неясно, что считать докладом | форма: причина, доказательства, следующий шаг |
| «Отладь это» | Codex остановится на первой гипотезе | `<default_follow_through_policy>` + `<completeness_contract>` |
| «Подумай как следует» | не меняет поведение | `<verification_loop>` |
| «Скажи точно, почему упал прод» | требование уверенности там, где её нет | `<grounding_rules>`: предположение помечать |
| ревью + починка + документация одним промптом | частичное выполнение всего | три запуска |

## Сборка промпта

1. `<task>`: работа, контекст, конец.
2. Наименьший контракт вывода, при котором ответом удобно пользоваться.
3. Решить: продолжать по умолчанию или останавливаться на недостающих деталях высокого риска.
4. Проверка, заземление, безопасность — только там, где задача этого требует.
5. Убрать повторы и общие слова перед отправкой.
