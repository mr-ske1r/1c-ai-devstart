## Паттерн: работа с журналом регистрации через БСП

**Почему:** БСП предоставляет обёртки для `ЗаписьЖурналаРегистрации()`, которые:
- Автоматически определяют метаданные объекта
- Корректно обрабатывают транзакции (запись в ЖР внутри транзакции может быть потеряна при откате)
- Форматируют сообщения по стандарту

### Правильно — через БСП

```bsl
// Логирование ошибки через обёртку БСП
Попытка
    ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);
Исключение
    ЗаписьЖурналаРегистрации(
        НСтр("ru = 'Проведение документа'",
            ОбщегоНазначения.КодОсновногоЯзыка()),
        УровеньЖурналаРегистрации.Ошибка,
        ДокументОбъект.Метаданные(),
        ДокументОбъект.Ссылка,
        ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    
    ВызватьИсключение;
КонецПопытки;
```

### Стандартные имена событий

```bsl
// Имена событий — иерархические, через точку
// Подсистема.Событие или Объект.Действие
ИмяСобытия = НСтр("ru = 'ОбменДанными.ОтправкаДанных'");
ИмяСобытия = НСтр("ru = 'Проведение документа.Ошибка'");
ИмяСобытия = НСтр("ru = 'ЗагрузкаДанных.ИзВнешнегоИсточника'");
```

## Паттерн: безопасное хранилище паролей

Используй его для паролей, токенов и закрытых API-ключей, которые необходимо сохранять в
информационной базе. Обычная константа или реквизит прикладного объекта не заменяют безопасное
хранилище.

| Действие | Метод `ОбщегоНазначения` |
|---|---|
| Записать | `ЗаписатьДанныеВБезопасноеХранилище()` |
| Прочитать | `ПрочитатьДанныеИзБезопасногоХранилища()` |
| Удалить | `УдалитьДанныеИзБезопасногоХранилища()` |

Секрет читай на сервере непосредственно перед использованием и не возвращай на клиент. В форме
храни только признак заполнения или уникальный идентификатор-заглушку, но не само значение.

Привилегированный режим включай в вызывающем коде на минимальное время и восстанавливай исходное
состояние на всех путях выхода:

```bsl
ИсходныйПривилегированныйРежим = ПривилегированныйРежим();
УстановитьПривилегированныйРежим(Истина);
Попытка
    Секреты = ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища(
        НастройкаИнтеграции,
        "ТокенДоступа");
    УстановитьПривилегированныйРежим(ИсходныйПривилегированныйРежим);
Исключение
    УстановитьПривилегированныйРежим(ИсходныйПривилегированныйРежим);
    ВызватьИсключение;
КонецПопытки;

ТокенДоступа = Секреты.ТокенДоступа;
```

Перед применением проверь сигнатуры методов в версии БСП проекта.

## Паттерн: временные файлы — создание платформой, удаление через ФайловаяСистема

> Норма об обязательном удалении, в том числе на пути исключения, — std#542 в `.claude/rules/1c-rules.md`.

**Почему:** `ПолучитьИмяВременногоФайла()` создаёт файл, но не удаляет его — удаление остаётся обязанностью кода. Методы удаления модуля БСП `ФайловаяСистема` лучше прямого `УдалитьФайлы()`: они проверяют, что путь действительно временный (защита от удаления не того файла), а если файл занят другим процессом — пишут предупреждение в журнал регистрации и не роняют основную операцию.

| Действие | Метод |
|---|---|
| Создать временный файл | `ПолучитьИмяВременногоФайла()` (платформа) |
| Создать временный каталог | `ФайловаяСистема.СоздатьВременныйКаталог()`, на клиенте — `ФайловаяСистемаКлиент.СоздатьВременныйКаталог()` |
| Удалить временный файл | `ФайловаяСистема.УдалитьВременныйФайл()` |
| Удалить временный каталог с содержимым | `ФайловаяСистема.УдалитьВременныйКаталог()` |

### Пример: временный файл с удалением на всех путях выхода

```bsl
ИмяВременногоФайла = ПолучитьИмяВременногоФайла("xlsx");
Попытка
    ТабличныйДокумент.Записать(ИмяВременногоФайла, ТипФайлаТабличногоДокумента.XLSX);
    // ... работа с файлом ...
Исключение
    ФайловаяСистема.УдалитьВременныйФайл(ИмяВременногоФайла);
    ВызватьИсключение;
КонецПопытки;

ФайловаяСистема.УдалитьВременныйФайл(ИмяВременногоФайла);
```

Не путай с подсистемой «Работа с файлами» (модуль `РаботаСФайлами`): она про файлы, присоединённые к объектам базы (`ДвоичныеДанныеФайла()`, `ДобавитьФайлСДиска()`), а не про утилитарные операции с файловой системой.

## Паттерн: ДлительныеОперации — фоновое выполнение через БСП

> Норма о выборе фонового выполнения — в `.claude/rules/1c-rules.md`. Здесь приведён паттерн реализации через БСП.

**Почему:** прямой `ФоновыеЗадания.Выполнить()` не даёт контроля завершения, передачи результата, обработки ошибок и индикации прогресса. Подсистема БСП «Длительные операции» решает всё это: результат возвращается через временное хранилище, пользователь видит прогресс и может отменить операцию.

```bsl
// ✅ ПРАВИЛЬНО: запуск и ожидание через БСП

&НаКлиенте
Процедура ВыполнитьОбработку(Команда)

    РезультатЗапуска = ЗапуститьОбработкуНаСервере(УникальныйИдентификатор);

    ПараметрыОжидания = ДлительныеОперацииКлиент.ПараметрыОжидания(ЭтотОбъект);
    Оповещение = Новый ОписаниеОповещения("ПослеВыполненияОперации", ЭтотОбъект);
    ДлительныеОперацииКлиент.ОжидатьЗавершение(РезультатЗапуска, Оповещение, ПараметрыОжидания);

КонецПроцедуры

&НаСервере
Функция ЗапуститьОбработкуНаСервере(ИдентификаторФормы)

    ПараметрыВыполнения = ДлительныеОперации.ПараметрыВыполненияФункции(ИдентификаторФормы);
    ПараметрыВыполнения.НаименованиеФоновогоЗадания = НСтр("ru = 'Обработка данных'");

    Возврат ДлительныеОперации.ВыполнитьФункцию(
        ПараметрыВыполнения,
        "МойМодуль.ОбработатьДанные",
        ПараметрыОбработки);

КонецФункции

&НаКлиенте
Процедура ПослеВыполненияОперации(Результат, ДополнительныеПараметры) Экспорт

    Если Результат = Неопределено Тогда // пользователь отменил операцию
        Возврат;
    КонецЕсли;

    Если Результат.Статус = "Ошибка" Тогда
        ВызватьИсключение Результат.КраткоеПредставлениеОшибки;
    КонецЕсли;

    ОбработатьРезультат(Результат.АдресРезультата); // результат — во временном хранилище

КонецПроцедуры

// ❌ ПЛОХО: прямой запуск фонового задания
ФоновыеЗадания.Выполнить("МойМодуль.ОбработатьДанные", ПараметрыВызова);
// Нет контроля завершения, результата, прогресса и обработки ошибок
```

Обработчик завершения через `ОписаниеОповещения` здесь определяется контрактом API БСП (`ОжидатьЗавершение`). Настройка стиля проекта применяется только когда используемый программный интерфейс предоставляет оба варианта.

## Паттерн: типовые паттерны БСП для конкретных задач

### Паттерн: Проверка заполнения (ОбработкаПроверкиЗаполнения)

> Здесь — оформление сообщения средствами БСП. Когда платформа вызывает этот обработчик, чего
> в него класть нельзя и как оформлять условную проверку — скилл `obj-lifecycle`.

```bsl
// Модуль объекта — стандартный обработчик проверки заполнения
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)
    
    // Добавляем свои проверки к стандартным
    Если НЕ ЗначениеЗаполнено(Контрагент) Тогда
        ОбщегоНазначения.СообщитьПользователю(
            НСтр("ru = 'Не заполнен контрагент.'"),
            ЭтотОбъект, "Контрагент",, Отказ);
    КонецЕсли;
    
    // Условное исключение реквизитов из проверки
    // (например, если вид операции не требует склада)
    Если ВидОперации = Перечисления.ВидыОпераций.Услуга Тогда
        ОбщегоНазначенияКлиентСервер.УдалитьЗначениеИзМассива(
            ПроверяемыеРеквизиты, "Склад");
    КонецЕсли;
    
КонецПроцедуры
```

### Паттерн: Получение данных для печати

```bsl
// Использование модуля УправлениеПечатью для формирования печатных форм
Процедура Печать(МассивОбъектов, ПараметрыПечати, КоллекцияПечатныхФорм,
        ОбъектыПечати, ПараметрыВывода) Экспорт
    
    Если УправлениеПечатью.НужноПечататьМакет(КоллекцияПечатныхФорм, "Счёт") Тогда
        
        ТабличныйДокумент = Новый ТабличныйДокумент;
        ТабличныйДокумент.КлючПараметровПечати = "Документ.РеализацияТоваровУслуг.Счёт";
        
        // ... формирование печатной формы ...
        
        УправлениеПечатью.ВывестиТабличныйДокументВКоллекцию(
            КоллекцияПечатныхФорм, "Счёт", НСтр("ru = 'Счёт на оплату'"),
            ТабличныйДокумент);
    КонецЕсли;
    
КонецПроцедуры
```

### Паттерн: Работа с правами доступа

Специальной обёртки для проверки права на объект в БСП нет — не изобретай методов вида `ОбщегоНазначения.ПравоДоступаОбъекта()`. Сама БСП проверяет права платформенной функцией `ПравоДоступа()`:

```bsl
Если НЕ ПравоДоступа("Изменение", Метаданные.Документы.РеализацияТоваровУслуг) Тогда
    ВызватьИсключение НСтр("ru = 'Недостаточно прав для изменения документов реализации.'");
КонецЕсли;
```
