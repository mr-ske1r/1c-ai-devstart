## Паттерн: ЗаписьЖурналаРегистрации — правильное логирование

**Почему:** Журнал регистрации (ЖР) — основной инструмент диагностики проблем в продуктиве. Без структурированных логов разбор инцидентов превращается в гадание. Правильное логирование:
- Позволяет найти проблему за минуты, а не за часы
- Даёт контекст: что произошло, с каким объектом, кто инициировал
- Фильтруется по уровню, событию, объекту, пользователю

### Полный формат записи

```bsl
ЗаписьЖурналаРегистрации(
    ИмяСобытия,         // Строка — иерархическое имя (через точку)
    УровеньСобытия,     // УровеньЖурналаРегистрации — Ошибка/Предупреждение/Информация/Примечание
    МетаданныеОбъекта,  // Объект метаданных — для фильтрации по типу
    Данные,             // Ссылка на объект — для навигации из ЖР
    Комментарий);       // Строка — подробное описание (до 1024 символов)
```

### Уровни и когда их использовать

| Уровень | Когда | Пример |
|---------|-------|--------|
| `Ошибка` | Операция не выполнена, данные потеряны или некорректны | Ошибка записи, откат транзакции |
| `Предупреждение` | Операция выполнена, но с ограничениями | Документ записан без проведения, данные неполные |
| `Информация` | Значимые события для аудита | Пользователь удалил 100 элементов, обмен данными завершён |
| `Примечание` | Диагностическая информация | Длительность операции, параметры вызова |

### Пример: структурированное логирование

```bsl
// Имя события — иерархическое, для фильтрации
// Формат: Подсистема.Событие или Объект.Действие
ИмяСобытия = НСтр("ru = 'ОбменДанными.ОтправкаДанных.Ошибка'");

// Комментарий — максимум информации для диагностики
Комментарий = СтрШаблон(
    НСтр("ru = 'Ошибка при отправке данных в узел ""%1"".
    |Количество объектов: %2.
    |Текст ошибки:
    |%3'"),
    Строка(УзелОбмена),
    КоличествоОбъектов,
    ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));

ЗаписьЖурналаРегистрации(
    ИмяСобытия,
    УровеньЖурналаРегистрации.Ошибка,
    Метаданные.ПланыОбмена.ОбменСКонтрагентами,
    УзелОбмена,
    Комментарий);
```

## Паттерн: что нельзя логировать

**Почему:** Журнал регистрации хранится долго и доступен пользователям с правом просмотра. Секреты и ПДн в логе — утечка; большие данные — раздувание журнала.

- Не пиши в `ЗаписьЖурналаРегистрации` пароли, токены, cookies, номера карт, персональные данные, полные тела запросов — даже в подробном представлении ошибки (проверяй текст, если он может их содержать).
- Маскируй чувствительные заголовки и секретные параметры URL.
- Большие коллекции заменяй сводкой: количество, диапазон, безопасные идентификаторы — не сама коллекция.
- Не логируй одно исключение повторно на каждом уровне стека (норма [std#499] + «логируй раз на границе»).
- Для интеграций логируй: идентификатор корреляции, метод, адрес без секретных параметров, код ответа, длительность.

## Паттерн: когда запись в журнал нужна, а когда нет

**Почему:** Запись в журнал из кода нужна, когда администратору требуется диагностика, которую платформа не пишет сама ([std#498] п. 2). Лишние записи раздувают журнал и прячут в нём настоящие ошибки.

Пиши:
- в блоке `Исключение` транзакции — после `ОтменитьТранзакцию()` ([std#783]);
- при окончательной обработке без проброса: ошибка элемента массовой операции, фоновое или регламентное задание, продолжающее работу ([std#499] п. 3.2);
- о неудачной промежуточной попытке внешнего вызова, которую код повторит, — уровнем «Предупреждение»;
- о событиях, которые нужны администратору для разбора работы механизма или требуются задачей для аудита, — например, начало и завершение длительного обмена ([std#498] п. 2).

Не пиши:
- о необработанном исключении — его записывает платформа; перехват ради записи с последующим пробросом даёт вторую запись ([std#499] п. 1);
- об исключении, перевызванном с уточнением, — его запишет окончательный обработчик или платформа;
- о штатных шагах обычной доработки — «начали», «обработали строку», «завершили», — если администратору они для диагностики не нужны и задача их не требует. Это решение шаблона, а не прямая норма: стандарт допускает такие записи, когда диагностика нужна.

## Паттерн: формирование сообщений об ошибках для пользователя

**Почему:** Пользователь — не разработчик. Сообщение «{ОбщийМодуль.МодульОбработкиДанных.Модуль(123)}: Ошибка при вызове метода контекста» — бесполезно. Пользователю нужно знать:
1. **Что произошло** (простыми словами)
2. **Что делать** (повторить, обратиться к администратору, проверить данные)
3. **Куда обратиться** за помощью

Необработанное исключение платформа показывает пользователю сама, с текстом и категорией ошибки ([std#499] п. 1). Поэтому первый вариант — не перехватывать: текст ошибки проведения, проверки данных или нарушения прав пользователю понятен и так. Уточнение нужно, когда исходный текст ничего не скажет пользователю: внешний ресурс, интеграция, файл ([std#499] п. 2). Как выглядит окно ошибки, проверяй без отладки и без режима технического специалиста: в этих режимах оно выглядит иначе.

### Правильно — пояснение поверх исходного текста

Образцы — Шаблон 2 в `../SKILL.md` (с БСП) и «Пример: уточнение без БСП» в `exceptions.md`. Пояснение говорит, что не удалось и что делать; исходная ошибка передаётся последним параметром `ВызватьИсключение` и остаётся в `Причине`.

### Неправильно — запись в журнал и перевызов строкой

```bsl
// ❌ ПЛОХО: двойная запись в журнал и потеря исходной ошибки
Попытка
    ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);
Исключение
    ЗаписьЖурналаРегистрации(
        НСтр("ru = 'Проведение документа'"),
        УровеньЖурналаРегистрации.Ошибка,
        ДокументОбъект.Метаданные(),
        ДокументОбъект.Ссылка,
        ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    ВызватьИсключение СтрШаблон(
        НСтр("ru = 'Не удалось провести документ: %1'"),
        ОбработкаОшибок.КраткоеПредставлениеОшибки(ИнформацияОбОшибке()));
КонецПопытки;
```

Что здесь не так:
- новое исключение запишут в журнал ещё раз — окончательный обработчик или платформа, — и одна ошибка даёт две записи;
- перевызов строкой теряет исходные категорию, стек и `Причину`;
- `КраткоеПредставлениеОшибки()` запрещён для пользователя ([std#499] п. 2.2).

Правильно здесь — убрать `Попытка` целиком: ошибка проведения дойдёт до пользователя и журнала без помощи кода.
