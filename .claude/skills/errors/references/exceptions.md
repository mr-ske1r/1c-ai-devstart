## Паттерн: Попытка/Исключение — перехватывай по сценарию, не гаси бесследно

**Почему:** Проглоченное (перехваченное бесследно) исключение — самый опасный антипаттерн. Система выглядит работающей, но:
- Данные не записаны / не обработаны
- Пользователь не знает об ошибке
- В журнале регистрации нет следов
- Отладка невозможна — воспроизвести проблему невозможно без логов

Обратная ошибка — перехват без необходимости. Перехват ради записи в журнал с последующим пробросом даёт двойную запись одной ошибки, а перевызов строкой теряет исходный текст и категорию.

**Стандарты (см. 1c-rules.md):** [std#499] не перехватывать без необходимости: необработанное исключение платформа сама показывает пользователю и записывает в журнал регистрации; перехваченное не гасить бесследно — перевызвать без потери исходной информации либо, при окончательной обработке, залогировать. [std#783] в блоке `Исключение` транзакции — откат, запись в журнал, перевызов. [std#498] писать в ЖР, когда админу нужна диагностика, которую платформа не пишет сама.

Сценарии, в которых `Попытка` нужна, перечислены в `../SKILL.md` («Шаблоны кода — выбери сценарий»).

### Пример: запись без перехвата

```bsl
&НаСервереБезКонтекста
Процедура ПровестиДокументНаСервере(ДокументСсылка)
    ДокументОбъект = ДокументСсылка.ПолучитьОбъект();
    ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);
КонецПроцедуры

&НаКлиенте
Процедура Провести(Команда)
    Если Элементы.Список.ТекущаяСтрока = Неопределено Тогда
        Возврат;
    КонецЕсли;
    ПровестиДокументНаСервере(Элементы.Список.ТекущаяСтрока);
    Элементы.Список.Обновить();
КонецПроцедуры
```

`Попытка` нет ни на одном уровне. Если запись не удалась, платформа покажет пользователю текст ошибки и запишет её в журнал. Перехват здесь добавил бы только вторую запись в журнале и подменил бы точную причину общим «Обратитесь к администратору».

### Два представления ошибки

| Функция | Когда использовать | Что содержит |
|---------|-------------------|-------------|
| `ОбработкаОшибок.СообщениеОбОшибкеДляПользователя()` | Для отображения пользователю | Текст ошибки без стека вызовов; возвращает `ФорматированнуюСтроку`, при склейке со строкой и в `СтрШаблон` даёт обычную строку |
| `ОбработкаОшибок.ПодробноеПредставлениеОшибки()` | Для журнала регистрации | Полный стек вызовов, номера строк, вложенные ошибки |

`ОбработкаОшибок.КраткоеПредставлениеОшибки()` и `ОписаниеОшибки()` не используй (std#499 п. 2.2).

## Паттерн: правильный проброс исключений — ВызватьИсключение

**Почему:** В BSL есть три способа вызвать исключение в блоке `Исключение`:
1. `ВызватьИсключение;` (без параметра) — пробрасывает **оригинальное** исключение с полным стеком вызовов
2. `ВызватьИсключение(Текст, Категория, Код, ДополнительнаяИнформация, Причина)` — создаёт **новое** исключение с уточнённым текстом, а исходное сохраняет в `Причине`
3. `ВызватьИсключение ТекстСообщения;` (со строкой) — создаёт **новое** исключение, исходный текст, категория и стек теряются

### Когда что использовать

| Способ | Когда | Почему |
|--------|-------|--------|
| `ВызватьИсключение;` | В блоке транзакции, после восстановления состояния | Сохраняет оригинальный стек — легче диагностировать |
| `ВызватьИсключение(Текст, Категория, , ДляАдминистратора, ИнформацияОбОшибке)` | Технический текст непонятен пользователю — внешний ресурс, интеграция, файл | Пользователь видит пояснение, администратор — исходную ошибку (std#499 п. 2.1) |
| `ВызватьИсключение "Текст";` | Собственная ошибка, не связанная с перехваченной: не выполнено условие, неверные данные | В блоке `Исключение` не используй — теряет исходную ошибку |

### Пример: уточнение без БСП

С БСП — `ОбщегоНазначенияКлиентСервер.УточнениеИсключения()`, образец — Шаблон 2 в `../SKILL.md`.

```bsl
Попытка
    Ответ = Соединение.Получить(HTTPЗапрос);
Исключение
    ИнформацияОбОшибке = ИнформацияОбОшибке();
    ТекстСообщения = НСтр("ru = 'Не удалось получить курсы валют с сайта банка:'")
        + Символы.ПС + ОбработкаОшибок.СообщениеОбОшибкеДляПользователя(ИнформацияОбОшибке)
        + Символы.ПС + НСтр("ru = 'Проверьте подключение к интернету и настройки прокси-сервера.'");
    ВызватьИсключение(ТекстСообщения, , , АдресСервиса, ИнформацияОбОшибке);
КонецПопытки;
```

Четвёртый параметр — сведения для администратора, которых нет в исходной ошибке; здесь адрес сервиса без секретных параметров.

## Паттерн: обработка ошибок при массовых операциях

**Почему:** При обработке массива документов (пакетное проведение, обмен данными) ошибка в одном документе не должна останавливать обработку остальных. Но каждая ошибка должна быть залогирована.

### Паттерн: поэлементная обработка с накоплением ошибок

```bsl
Процедура ПровестиДокументыПакетно(МассивДокументов)
    
    МассивОшибок = Новый Массив;
    
    Для Каждого ДокументСсылка Из МассивДокументов Цикл
        
        НачатьТранзакцию();
        Попытка
            
            ДокументОбъект = ДокументСсылка.ПолучитьОбъект();
            ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);
            
            ЗафиксироватьТранзакцию();
        Исключение
            ОтменитьТранзакцию();
            
            ИнфоОшибки = ИнформацияОбОшибке();
            
            // Логируем каждую ошибку отдельно
            ЗаписьЖурналаРегистрации(
                НСтр("ru = 'Пакетное проведение'"),
                УровеньЖурналаРегистрации.Ошибка,
                ДокументСсылка.Метаданные(),
                ДокументСсылка,
                ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнфоОшибки));
            
            // Накапливаем для итогового отчёта
            МассивОшибок.Добавить(Новый Структура("Документ, Ошибка",
                ДокументСсылка,
                ОбработкаОшибок.СообщениеОбОшибкеДляПользователя(ИнфоОшибки)));
            
            // НЕ прерываем цикл — продолжаем с остальными документами
        КонецПопытки;
        
    КонецЦикла;
    
    // Итоговый отчёт
    Если МассивОшибок.Количество() > 0 Тогда
        ТекстИтога = СтрШаблон(
            НСтр("ru = 'Обработано документов: %1. Ошибок: %2.'"),
            МассивДокументов.Количество(),
            МассивОшибок.Количество());
        
        // Выводим ошибки пользователю
        Для Каждого ОшибкаДокумента Из МассивОшибок Цикл
            ОбщегоНазначения.СообщитьПользователю(
                СтрШаблон(НСтр("ru = 'Документ %1: %2'"),
                    ОшибкаДокумента.Документ, ОшибкаДокумента.Ошибка));
        КонецЦикла;
    КонецЕсли;
    
КонецПроцедуры
```

## Паттерн: Попытка/Исключение для внешних вызовов

**Почему:** Вызовы внешних систем (HTTP, почта, файловые операции) ненадёжны по определению: сеть может быть недоступна, файл — заблокирован, сервис — перегружен. Такие вызовы **всегда** оборачиваются в `Попытка/Исключение` с осмысленной обработкой.

### Паттерн: HTTP-вызов с повторными попытками

```bsl
Функция ОтправитьДанныеВоВнешнююСистему(Данные)
    
    МаксимумПопыток = 3;
    
    Для НомерПопытки = 1 По МаксимумПопыток Цикл
        
        Попытка
            
            HTTPСоединение = Новый HTTPСоединение("api.example.com",,,,, 30); // таймаут 30 сек
            Запрос = Новый HTTPЗапрос("/api/data");
            Запрос.УстановитьТелоИзСтроки(Данные);
            
            Ответ = HTTPСоединение.ОтправитьДляОбработки(Запрос);
            
            Если Ответ.КодСостояния = 200 Тогда
                Возврат Истина;
            Иначе
                ВызватьИсключение СтрШаблон(
                    НСтр("ru = 'Сервер вернул код %1: %2'"),
                    Ответ.КодСостояния,
                    Ответ.ПолучитьТелоКакСтроку());
            КонецЕсли;
            
        Исключение
            
            Если НомерПопытки = МаксимумПопыток Тогда
                ВызватьИсключение;
            КонецЕсли;
            
            ЗаписьЖурналаРегистрации(
                НСтр("ru = 'Интеграция.ОтправкаДанных'"),
                УровеньЖурналаРегистрации.Предупреждение,,,
                СтрШаблон(НСтр("ru = 'Попытка %1 из %2. Ошибка: %3'"),
                    НомерПопытки, МаксимумПопыток,
                    ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())));
            
            // Пауза перед повторной попыткой (exponential backoff)
            // В 1С нет встроенного Sleep, но можно использовать обработчик ожидания
            
        КонецПопытки;
        
    КонецЦикла;
    
    Возврат Ложь;
    
КонецФункции
```

Неудачные промежуточные попытки платформа не записывает — их пишет код, уровнем «Предупреждение». Ошибку последней попытки код не записывает, а пробрасывает: в журнал она попадёт один раз — при окончательной обработке или как необработанное исключение.
