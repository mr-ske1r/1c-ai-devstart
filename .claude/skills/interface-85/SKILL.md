# Проектирование форм для интерфейса «Версия 8.5»

Этот skill отвечает за компоновку, UX, визуальный слой и стратегию перехода. Код формы,
обработчики и программное создание элементов — область `form-work`.

## 1. Сначала определи фактический интерфейс

Следуй `.claude/rules/mcp.md` и самостоятельно прочитай в конфигурации свойство
`Режим совместимости интерфейса`. Не спрашивай пользователя о факте, который доступен через
MCP, индекс или исходники проекта.

Разделяй:

- версию технологической платформы;
- `Режим совместимости` конфигурации;
- `Режим совместимости интерфейса`.

Упоминание платформы 8.5 или режима совместимости конфигурации само по себе не означает
интерфейс «Версия 8.5».

Классифицируй состояние проекта:

| Значение свойства | Состояние проекта |
|---|---|
| `Такси` | Taxi-only: не применяй рекомендации 8.5, если переход не входит в задачу |
| `Версия 8.5` | 85-only |
| `Такси. Разрешить Версия 8.5` | переходный режим, по умолчанию «Такси» |
| `Версия 8.5. Разрешить Такси` | переходный режим, по умолчанию «Версия 8.5» |

Если конфигурация недоступна, спроси только текущее значение свойства. Если пользователь просит
целевой режим, отличный от фактического, назови расхождение и уточни цель только тогда, когда она
не следует из задачи.

## 2. Отдельно классифицируй артефакт

Состояние проекта и совместимость формы или макета — разные оси. Для каждого артефакта выбери:

- только «Версия 8.5»;
- один артефакт для «Такси» и «Версия 8.5»;
- отдельные артефакты для двух интерфейсов.

Метки в references независимы:

- `NEW-85` — новое проектирование для 8.5;
- `MIGRATION-85` — действия при переходе;
- `DUAL-TAXI-85` — один артефакт должен работать в обоих интерфейсах.

Одна рекомендация может иметь несколько меток. Для Taxi-only без перехода остановись и не читай
references этого skill.

## 3. Собери минимально необходимые факты

- пользовательский сценарий, порядок ввода и важность данных;
- тип формы и крупные элементы: таблицы, дерево, табличный документ, HTML;
- целевые клиенты и разрешения;
- светлая/тёмная тема и масштаб, если они входят в приёмку;
- фактический и целевой интерфейс;
- требуется ли один артефакт для двух интерфейсов.

`mobile` не является достаточным ответом: уточни, имеется в виду мобильный клиент, мобильное
приложение или веб-клиент на телефоне.

## 4. Исследуй существующую форму

Читай фактическую структуру, свойства и вызовы по `.claude/rules/mcp.md`. Индекс исходников может
не знать XML формы — тогда используй исходники из каталогов проекта. Не выдумывай элементы и
свойства.

Этот skill не описывает XML и не разрешает его менять. Для физического изменения используй
доступный инструментальный skill и полномочия из `CLAUDE.md` проекта.

## 5. Загрузи только нужную справку

| Задача | Reference |
|---|---|
| Новая форма, перепроектирование, ревью компоновки, элементы, команды, таблицы, отчёты | `references/form-design.md` |
| Цвета, шрифты, картинки, темы, HTML-поле, табличный документ | `references/visual-style.md` |
| Генерация или ревью HTML, которому нужны цвета интерфейса | дополнительно `references/html-colors.md` |
| Переход, совместная работа, дополнительные формы, конвертер, одна или две формы | `references/migration.md` |

Для реализации кода, событий и программного создания реквизитов или элементов дополнительно
загрузи `form-work`. Не копируй из него компоновку 8.3 в решение для 8.5.

## 6. Выдай результат по режиму задачи

### Новая форма или перепроектирование

1. Сценарий пользователя и приоритет данных.
2. Выбранный архетип и дерево элементов/групп.
3. Размещение и важные свойства команд, таблиц, итогов и подвала.
4. Адаптивность и визуальное оформление.
5. Матрица применимых клиентов, разрешений, тем и масштабов.

### Ревью существующей формы

Сначала дай вывод о пригодности. Затем перечисли находки по убыванию влияния в формате:

`место → наблюдаемое отклонение → последствие для пользователя → конкретное изменение`.

После находок укажи, что исследовано и что нельзя подтвердить без запуска клиента.

### Миграция

`целевой охват → стратегия и причина → порядок форм/рабочих мест → одна или две формы →
конвертация и ручная доработка → пилот и откат → завершение и очистка`.

## 7. Не завышай уровень проверки

Для каждой клетки матрицы ставь один статус:

- `расчётная статическая проверка`;
- `подтверждено запуском в клиенте`;
- `не проверено`.

Статический разбор XML не подтверждает фактический внешний вид, прокрутку, масштаб или поведение
темы. Не пиши «проверено», если клиент не запускался.
