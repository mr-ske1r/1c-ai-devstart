# Работа с базой через MCP-сервер

Полная схема параметров и допустимых значений каждого инструмента приходит вместе с самим
инструментом — не копируй её отсюда. Нормы (что обязательно до кода, что нельзя без разрешения
пользователя) — в `.claude/rules/mcp.md`. Здесь — порядок работы, смысл параметров и поведение,
которых недостаточно видно из схемы.

## Порядок работы с данными базы

1. `list_metadata_objects` — найти объект, если точное имя неизвестно (маска ищет и в синониме).
2. `get_metadata_structure` — взять реальные имена и типы реквизитов, ТЧ, значения перечислений.
3. Написать запрос по полученным именам.
4. `validate_query` — проверить синтаксис и существование таблиц.
5. `execute_query` — выполнить (значения подставляй в текст: параметры запроса не поддерживаются).

Какие регистры двигает документ и в какие подсистемы входит объект — секции `register_records`
и `subsystems` у `get_metadata_structure` (по умолчанию `subsystems` не выводится), а не поиск
по коду: ответ уже с учётом расширений.

Для журнала: сначала `eventlog_filter_values` (точные внутренние имена событий и пользователей),
потом `eventlog_query` — угаданное имя даёт пустую выборку, а не ошибку.

## Порядок работы с хранилищами настроек платформы

Этот раздел применяй только если задача прямо требует прочитать или изменить конкретную настройку.
Например, «покажи значение настройки X» или «измени настройку X для пользователя Y». Для обычной
разработки, а также из-за упоминания пароля, токена или учётных данных эти инструменты не вызывай.

`storage_reader` и `set_storage_value` работают со стандартными хранилищами платформы:

- `CommonSettings` — хранилище общих настроек;
- `SystemSettings` — хранилище системных настроек;
- `FormDataSettings` — хранилище настроек данных форм.

Они не читают и не изменяют БСП «Безопасное хранилище паролей».

Это не объекты метаданных типа `ХранилищеНастроек`: найденное через `list_metadata_objects`
прикладное хранилище нельзя передать как `storageType`.

Платформа не позволяет перечислить разделы хранилища. `objectName` (ключ объекта, то есть раздел)
нужно знать из задачи или найти в коде. Если раздел известен, а ключ настройки нет — сначала вызови
`storage_reader` с действием `get_list`, затем читай описание или значение нужного ключа. Вложенное
свойство и страницу табличного значения выбирай параметрами из схемы инструмента.

Если настройка зависит от пользователя, укажи `userName` осознанно: без него сервер работает от
имени текущего пользователя своего сеанса.

Отсутствие даты изменения и признака сжатия в результате `get_description` не является ошибкой:
стандартные хранилища платформы эти сведения не предоставляют. Правила подтверждения записи через
`set_storage_value` — в `.claude/rules/mcp.md`.

## Справка платформы (`platform_help`)

Справка синтакс-помощника: глобальные методы, типы и их члены, конструкторы, события, операторы
встроенного языка, язык запросов. Порядок проверки метода:

1. `platform_help` с `query` — имя по-русски или по-английски, член типа через точку
   (`ЧтениеZipФайла.Открыть`). Одно совпадение — сразу карточка; несколько — список, открывай
   нужную строку её путём в `path`. Длинная карточка приходит частями — следующую называет
   последняя строка, бери её через `part`.
2. По карточке сверь сигнатуру, «Доступность» (клиент, сервер, внешнее соединение — под контекст
   модуля) и «Версии». Первая строка ответа называет версию платформы и режим совместимости
   конфигурации: метод с «Доступен с версии» новее режима совместимости — неприменим.
3. Строки `примечание:` в начале ответа — предупреждения, а не шум: «не рекомендуется использовать,
   начиная с версии …» означает, что метод заменён (замена названа в «Версиях»).

- Ветка поиска — в статусной строке (`поиск: точное`, затем начало, вхождение, полнотекстовый).
  `полнотекстовый` значит, что по имени не нашлось и в списке страницы, где слово встречается
  в описании: метода с таким именем это не подтверждает.
- Операторы языка и запросов ищи с фильтром `kind` (`язык`, `запрос`) — иначе `ПОДОБНО` или
  `Неопределено` утонут среди методов.
- Ответ, начинающийся с `{`, — отказ в JSON: `NothingFound` (прошли все ветки, метода нет —
  перед выводом попробуй второе написание имени), `IndexBuilding` (индекс этой версии строится —
  повтори позже, нулём не считай), `VersionNotFound` (версия не индексирована, доступные —
  в `allowedValues`). Что из них допустимо выдавать за доказательство — норма в `.claude/rules/mcp.md`.
- Пути (`path`) действуют только в пределах своей версии платформы.
- Состояние индекса — `platform_help_index` с `status`: версии, прогресс сборки, найден ли файл
  справки на сервере. Первый вызов для неиндексированной версии сам запускает сборку на несколько
  минут. Правила для `rebuild` и `delete` — в `.claude/rules/mcp.md`.

## Структура хранения (`db_tables`, `db_table_fields`)

Нужна, когда на руках имя таблицы или поля СУБД — из технологического журнала, SQL-трассировки,
плана запроса, сообщения о блокировке: `db_tables` по `_Reference15` называет объект и вид таблицы
(основная, табличная часть, регистрация изменений, итоги), `db_table_fields` по имени таблицы —
поля с именами реквизитов. С `includeIndexes` — состав индексов: так проверяют, есть ли индекс
под отбор, не гадая по метаданным. Обратная задача (объект → его таблицы) — тот же `db_tables`
по имени объекта. Для обычной разработки и запросов на языке 1С не нужны: там хватает
`get_metadata_structure`.

## Поведение сервера (проверено на демо-базе БСП)

- `metaType` — по-английски (`Catalogs`), `name` — как в конфигурации, обычно по-русски
  (`_ДемоКонтрагенты`). `Catalogs` + `Users` даёт «объект метаданных не найден».
- Метаданные отдаются **с учётом применённых расширений**: объекты и реквизиты из расширений видны
  наравне с основной конфигурацией. Чего MCP не даёт — тексты модулей, формы, внешние обработки:
  за ними иди по приоритету источников из `.claude/rules/mcp.md` (индекс исходников, затем исходники проекта).
- Ссылочные поля в результате запроса приходят представлением (`"Контрагент": "ООО \"Альфа\""`),
  а не GUID — для идентификации объекта запрашивай код, номер или используй `ЗНАЧЕНИЕ()`.
- Изредка (порядка одного вызова из полутора десятков) сервер отвечает ошибкой
  `Тип не определен '<guid>'` на запросе, который до и после этого отрабатывает штатно. Причина не
  установлена. Получив её — просто повтори вызов, не переписывай запрос.
- `execute_code` возвращает результат через предопределённую переменную `__Возврат`; если её не
  заполнить, результата не будет.
- Для отсутствующего ключа `storage_reader` не обязательно возвращает ошибку инструмента:
  `get_description` сообщает `exists: false`, а `get_value` — тип `Undefined`. Проверяй содержимое
  ответа, а не только признак успешного вызова MCP.

## Ресурс сервера

`file://resource/syntax_1c.txt` — краткая шпаргалка по синтаксису встроенного языка. Полезна для
базового синтаксиса; методы платформы по ней не проверить — для них `platform_help`, если он
есть в сессии; методы БСП — по исходникам.

## Подключение

Сервер даёт расширение [1c_mcp](https://github.com/vladimir-kharin/1c_mcp): оно устанавливается
в базу и реализует протокол MCP как HTTP-сервис, база публикуется на веб-сервере — локальном
(`localhost`) или общем. Адрес сервиса: `http://<адрес сервера>/<имя публикации>/hs/mcp/`.

Сервера Claude Code прописываются в `.mcp.json` в корне проекта (образец — `.mcp.json.example`). Cursor читает `.cursor/mcp.json` (образец — `.cursor/mcp.json.example`): каталог с точкой, имя файла без точки. Это не корневой `mcp.json`. Одна папка проекта — не обязательно одна база: рядом с основной подключают тестовую копию, базу клиента, базу смежной системы для интеграционной задачи.

**Имя сервера выбирает пользователь, и по нему должно читаться, что за база.** В Claude Code оно попадает в имя каждого инструмента (`mcp__<имя сервера>__<инструмент>`). В Cursor имя инструмента не меняется, а имя сервера видно в списке, куда клиент этот инструмент положил. При нескольких базах серверы различаются этим, а не похожестью имён. Хорошее имя называет конфигурацию и контур:

```json
{
  "mcpServers": {
    "ut-test": {
      "type": "http",
      "url": "http://localhost/ut_test/hs/mcp/"
    },
    "ut-prod": {
      "type": "http",
      "url": "http://server/ut/hs/mcp/"
    }
  }
}
```

Каждую добавленную базу занеси строкой в секцию «Подключённые базы (MCP)» файла `CLAUDE.md` — правила выбирают базу по ней. Не занесённая база для агента рабочая: писать в неё он не станет. Со второй базы пометь одну строку как базу по умолчанию, иначе агент будет переспрашивать при каждой задаче, где база не названа.

Тот же список в `.cursor/mcp.json` — без поля `type`, Cursor для HTTP-сервера читает только `url` ([cursor.com/docs/mcp](https://cursor.com/docs/mcp)):

```json
{
  "mcpServers": {
    "ut-test": {
      "url": "http://localhost/ut_test/hs/mcp/"
    }
  }
}
```

Если публикация закрыта Basic-авторизацией — заголовок с учётными данными из переменной окружения, а не в открытом виде в файле. Синтаксис разный: Claude Code в `.mcp.json` разворачивает `${VAR}`, Cursor в `.cursor/mcp.json` — `${env:VAR}`.

```json
"headers": { "Authorization": "Basic ${ONEC_MCP_BASIC}" }
```

```json
"headers": { "Authorization": "Basic ${env:ONEC_MCP_BASIC}" }
```

**Компоненты.** Часть инструментов ставится не основным расширением, а отдельными
расширениями-компонентами — на вкладке «Компоненты» формы управления MCP-сервером в базе:
справка платформы (`platform_help`, `platform_help_index`), структура хранения (`db_tables`,
`db_table_fields`), выполнение кода (`execute_code`, с версии сервера 1.9.0). Нет такого
инструмента в сессии — значит, компонент в этой базе не установлен или отключён, а не сломан
сервер: скажи пользователю и иди по следующему источнику, не подменяй его другим инструментом.
Справке после установки компонента нужен индекс — первый вызов запустит его сборку.

Сервер из `.mcp.json` в Claude Code требует подтверждения при первом запуске; статус — командой `/mcp`.
В Cursor сервер из `.cursor/mcp.json` включается в настройках MCP и подхватывается после перезапуска окна.
Инструменты становятся доступны только при старте сессии: если сервер добавлен во время работы,
подключится он лишь после перезапуска того клиента, который этот файл читает.
