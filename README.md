# 1C AI DevStart

**Стартовый шаблон Claude Code для разработки на 1С:Предприятие 8.**

Готовый каталог `.claude/` для проекта вашей базы: правила кодирования по стандартам 1С,
скиллы с паттернами разработки на BSL, субагенты-роли и протокол работы с живой базой через MCP.
Скопируйте в проект, пройдите настройку одной командой - и агент начнёт писать код
по стандартам, сверяясь с метаданными реальной конфигурации, а не со своей памятью.

## Что умеет шаблон

- 📏 **Нормы BSL в одном месте** - правила кодирования по стандартам ИТС с единым
  чек-листом проверки; подключаются автоматически при работе с исходниками 1С.
- 🔌 **Источники истины вместо памяти** - протокол MCP: структура метаданных, проверка
  запросов и данные берутся из живой базы через MCP, тексты стандартов и диагностик -
  с v8std.ru (`v8std`). Агент не выдумывает реквизиты и не цитирует стандарты по памяти.
- 🧩 **16 скиллов разработки** - паттерны и практики для запросов, управляемых форм,
жизненного цикла объектов, транзакций и блокировок, БСП, СКД, расширений, интеграций,
обменов EnterpriseData и OData, а также пакетных операций с конфигуратором.
- 👥 **6 субагентов-ролей** - архитектор, исследователь кода, разработчик, ревьюер,
  упрощатель и составитель документации: тонкие роли без копий правил, каждый со своим фокусом.
- 🛂 **Полномочия под контролем** - паспорт проекта `CLAUDE.md` фиксирует, какие исходники
  агент вправе менять сам, какие - только по явному запросу, а какие лишь читать.
- ⚙️ **Пакетные операции** - выгрузка и загрузка конфигураций и расширений, сборка
  и разборка внешних обработок скриптами PowerShell через конфигуратор.

## Быстрый старт

Понадобятся: Windows, платформа 1С:Предприятие 8.3, установленный
[Claude Code](https://code.claude.com/docs) и PowerShell. Для работы MCP - расширение
[1c_mcp](https://github.com/vladimir-kharin/1c_mcp) Владимира Харина, установленное в вашу базу,
и публикация базы с его HTTP-сервисом на веб-сервере (локальном или общем).
Без него шаблон тоже работает, но агент лишится большого числа функциональных действий.

**1. Получите шаблон.** Скопируйте содержимое репозитория, кроме `README.md` и `install.md`,
в папку своего проекта 1С.

Шаблон - это просто набор файлов: `.claude/`, `CLAUDE.md` и заготовки каталогов.
Если брали шаблон клонированием, не переносите в проект папку `.git`.

Или поручите это агенту - откройте Claude Code в папке будущего проекта и напишите:
`Установи шаблон по инструкции https://raw.githubusercontent.com/mr-ske1r/1c-ai-devstart/master/install.md`

**2. Запустите настройку.** Откройте Claude Code в папке проекта и выполните:

```
/setup-project
```

Команда проведёт по шагам:

- **файлы окружения** - подключение к базе (путь к `1cv8.exe`, сервер и база, пользователь)
  и адрес MCP-сервиса. **Пароль вы вписываете в файл сами**: агент его не запрашивает
  и не видит, а сам файл в git не попадает;
- **исходники** - если `src/cf` пуст, предложит выгрузить конфигурацию в XML штатными
  средствами конфигуратора. Про расширения спросит, с какими работает ваш проект,
  и выгрузит только их: перебирать десятки расширений поставщика типовой конфигурации
  ни к чему. Выгрузили всё заранее сами - шаг просто пропускается;
- **паспорт проекта** `CLAUDE.md` - конфигурацию, версию, режим совместимости и префиксы
  расширений вычитает из исходников, вам останется подтвердить; префиксы и формат номера
  задачи спросит. Спросит и про маркеры доработок - нужны ли они вообще: команда умеет
  собрать паспорт как с маркерами, так и без них, если история правок у вас живёт в git;
- **полномочия** - какие исходники агент вправе менять сам, какие только по явному запросу,
  а какие лишь читать. По умолчанию предлагается осторожный набор: доверие к агенту проще
  наращивать, чем откатывать последствия.

Команда идемпотентна: сверяет фактическое состояние и доделывает недостающее. На второй
машине после клонирования вашего проекта просто запустите её ещё раз.

**3. Перезапустите сессию** - поднимутся MCP-серверы из `.mcp.json`. Проверьте, что
сервер вашей базы отвечает и видит вашу конфигурацию.

Готово: агент работает по правилам, видит метаданные базы и знает границы своих полномочий.

## Обновление шаблона

Скопируйте из репозитория папку `.claude` поверх своей. Файлы в корне - `CLAUDE.md`,
`.mcp.json`, настройки - не трогайте: они уже подогнаны под ваш проект.

Или поручите это агенту - откройте Claude Code в папке проекта и напишите:
`Обнови шаблон по инструкции https://raw.githubusercontent.com/mr-ske1r/1c-ai-devstart/master/install.md`

## Как работать с задачами

### Полный цикл

Для средних и сложных доработок запустите `1c-feature-dev`:

```
/1c-feature-dev Добавить интеграцию с API сервисдеска
```

Он проведёт задачу через анализ, исследование кода, проектирование, реализацию и ревью,
по необходимости подключая профильных субагентов. Рабочие артефакты сохраняются в `.tasks/`.
Это мощный многофазовый режим проработки вашей идеи задачи.

### Лёгкий цикл

Для небольших и понятных задач используйте две команды:

```
/new-brief @Задача.md
```
Сначала проверьте и при необходимости поправьте с агентом `brief.md`, затем вызывайте команду создания плана
```
/new-plan @docs/<задача>/brief.md
```
После этого передайте план агенту на реализацию:

```
Реализуй план @docs/<задача>/plan.md
```

### Субагенты отдельно

Полный цикл запускать необязательно. Любого субагента можно привлечь к отдельной задаче —
например, только исследовать код, спроектировать решение или проверить готовую реализацию:

```
Используй субагента 1c-code-reviewer и проверь изменения по задаче @docs/<задача>/brief.md
```

## Что внутри

```
.claude/
  rules/
    1c-rules.md          ← нормы BSL + чек-лист проверки кода (подключается на исходниках 1С)
    mcp.md               ← протокол источников истины: MCP → исходники → память с пометкой
    common-rules.md      ← общие правила поведения агента
  skills/                ← 16 скиллов: паттерны, примеры, ловушки
  agents/                ← 6 субагентов-ролей
  commands/              ← команды: /setup-project, /commit, документирование и планирование
CLAUDE.md                ← паспорт проекта (заполняется при настройке)
CLAUDE.local.md.example  ← личные настройки разработчика (не коммитится)
.mcp.json.example        ← подключение MCP-серверов: база проекта и v8std
.gitignore.example
src/
  cf/                    ← основная конфигурация
  cf_vendor/             ← эталон поставщика для сравнения (только чтение)
  cfe_<имя>/             ← расширения конфигурации
  epf/  erf/             ← внешние обработки и отчёты
tools/                   ← настройки подключения к базе для пакетных скриптов
docs/                    ← документация проекта: брифы, планы, описания объектов
```

## Скиллы

Скиллы содержат знания, паттерны и рабочие процессы разработки на 1С: как проектировать решение,
писать и проверять BSL-код, работать с запросами, формами, СКД, расширениями и интеграциями.

Обычно они подхватываются автоматически по описанию задачи. При необходимости скилл можно
запустить явно — как `1c-feature-dev` в примере выше.

| Скилл | Про что |
|---|---|
| `query-writing` | Запросы: пакетные, временные и виртуальные таблицы, NULL, наборы данных СКД |
| `skd-design` | Проектирование отчётов на СКД: наборы, ресурсы, параметры, варианты, программная компоновка |
| `form-work` | Знания о разработке управляемых форм: директивы, батчинг серверных вызовов, программные реквизиты и элементы, асинхронные диалоги |
| `obj-lifecycle` | Жизненный цикл объекта на сервере: порядок обработчиков при записи, проведении и отмене проведения, границы транзакции, наборы записей |
| `errors` | Исключения, транзакции, блокировки: канонический паттерн транзакции, deadlock, логирование |
| `use-bsp` | Переиспользование БСП: общие модули, права, файлы, длительные операции |
| `config-modification` | Оформление доработок: маркеры, расширения, директивы `&Перед`/`&После`/`&Вместо`/`&ИзменениеИКонтроль` |
| `extract-to-extension` | Перенос существующей доработки из типового объекта в расширение |
| `ssl-ext-commands` | Подключаемые команды БСП: печать, отчёты, ввод на основании |
| `1c-integrations` | HTTP-клиенты, JSON/XML, учётные данные, идемпотентность, ретраи |
| `enterprisedata-exch` | Обмены EnterpriseData через БСП: ПОД/ПКО/ПКС, XDTO, версии формата, публичные идентификаторы, диагностика по слоям |
| `1c-feature-dev` | Полный цикл доработки: от анализа и плана до реализации с проверками приёмки |
| `brainstorm` | Проработка требований и дизайна до начала реализации |
| `mcp-1c` | Работа с базой через MCP: метаданные, запросы, код на сервере, журнал регистрации |
| `1c-odata` | Чтение данных базы по OData - запасной путь, когда MCP недоступен |
| `1c-batch` | Пакетные операции с конфигуратором: выгрузка/загрузка конфигураций и расширений, сборка обработок |

## Как это устроено

Принцип **«ЧТО/КАК»** - у каждого факта один дом:

- **ЧТО** (нормы) живёт в `.claude/rules/1c-rules.md`: одна норма - одна строка, без примеров.
  Правило подключается только при работе с исходниками 1С и не занимает контекст зря.
- **КАК** (паттерны, примеры, ловушки) живёт в скиллах. Скилл ссылается на норму,
  а не копирует её.
- Субагенты - тонкие роли: не таскают копии правил, а ссылаются на общий чек-лист
  и протокол MCP.
- Паспорт `CLAUDE.md` - только факты вашего проекта: конфигурация, каталоги, префиксы,
  маркеры, полномочия.
- Инструменты физического изменения XML-исходников не дублируются внутри шаблона: для этого можно подключить специализированные внешние скиллы.

Такое разделение держит контекст агента компактным и исключает противоречия между копиями
одного и того же знания.

Отсюда следствия:

- **у каждой нормы указано происхождение** - `[std#404]` (номер страницы стандарта),
  `[платформа]`, `[рекомендация]`, `[правило проекта]`; наш собственный выбор вынесен
  в секцию «Политика шаблона» и ослабляется под проект. Видно, где стандарт, а где вкус;
- **чек-лист один на всех** - агенты разработчик, ревьюер и основная сессия сверяются по одному
  тексту, поэтому критерии приёмки не расходятся с критериями написания;
- **скилл ссылается на норму, а не пересказывает её** - правка нормы не оставляет
  разошедшихся копий в десятке файлов;
- **скиллы согласованы между собой** - области ответственности разграничены, пересекающиеся
  пары разведены заранее. На пограничной задаче агент берёт нужный скилл, а не всё похожее
  сразу.

Это не россыпь удачных подсказок в одной папке, а собранный каркас: нормы, знания, роли
и проверки подогнаны друг к другу.

## MCP-серверы

| Сервер | Что даёт | Откуда |
|---|---|---|
| Сервер вашей базы - имя задаёте вы | Метаданные, проверка и выполнение запросов, данные базы, журнал регистрации | [1c_mcp](https://github.com/vladimir-kharin/1c_mcp) Владимира Харина - расширение, публикуемое в вашей базе (адрес - в `.mcp.json`) |
| `v8std` | Тексты стандартов разработки 1С и описания диагностик АПК, BSLLS, EDT | Публичный сервер `ai.v8std.ru` проекта [v8std.ru](https://v8std.ru) |

Баз может быть несколько - рабочая, тестовая, база смежной системы. Каждая подключается
своим сервером в `.mcp.json` и заносится строкой в паспорт проекта: там указано, где
тестовый контур, а где рабочий, и что на каждой базе разрешено. Агент выбирает базу по этой
таблице и в базу, помеченную «только чтение», не пишет.

Шаблон работает и без MCP - тогда агент опирается на исходники проекта и честно помечает,
что не смог свериться с базой. Но полную силу протокол источников истины набирает
с подключённой базой.

## Рекомендуемое дополнение: cc-1c-skills

Шаблон намеренно не содержит инструментов для прямого изменения XML-исходников 1С. Для таких задач рекомендуется использовать [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills) Николая Широкова.

Эти скиллы дополняют шаблон инструментами для создания и изменения объектов метаданных,
управляемых форм, СКД и макетов с проверкой результата.

Таким образом, скиллы шаблона отвечают за правила, паттерны и процесс разработки,
а `cc-1c-skills` дополняют их инструментами для непосредственной работы со структурой XML-исходников 1С.
